# 온라인가나다 정기 보완 절차

국립국어원의 온라인가나다 질문·답변으로 한국어 스킬의 근거를 보완하고, 검토·검증한 변경을 일반 병합하기 위한 저장소 운영 절차다. 이 문서는 예약 실행기가 아니며, 반복 실행은 별도로 활성화된 자동화가 맡는다. 스킬의 원문 사용 기준은 [적용 범위와 근거 선택](../skills/korean-editing/references/scope-routing.md#온라인가나다-답변을-새-근거로-사용할-때)에 있다.

## 한 회차의 범위

1. 원격 `main`, 열린 PR의 head·base·실제 리뷰·검사를 다시 읽고 `AGENTS.md`·`CLAUDE.md`를 따른다. 이 작업의 미완료 PR이 있으면 그 PR부터 이어간다. 다른 담당자가 변경 중인 브랜치에는 동시에 쓰지 않는다.
2. [온라인가나다 목록](https://www.korean.go.kr/front/onlineQna/onlineQnaList.do?mn_id=201)의 새 질문·답변과 수정 공지를 확인한다. 답변이 달리지 않은 질문을 근거로 채택하지 않는다. 마지막 검토 뒤의 자료를 우선하되, 이미 인용한 답변 중 오래됐거나 상충·오류가 의심되는 항목도 재열람한다. 반환된 목록의 마지막 날짜와 실제 열람 범위를 기록한다. 검색·도구의 일부 결과를 게시판 전체 확인으로 보고하지 않는다.
3. 같은 `qna_seq`는 기존 출처 항목을 재사용한다. 한 회차에는 실제 규칙·출처 기록·허용 예를 개선하는 좁은 변경 묶음을 고른다. 원문 접근 실패만으로 내용을 삭제하거나 추정으로 고치지 않는다. 내용 변화가 없으면 날짜만 바꾸는 PR을 만들지 않는다.
4. 원문 제목·질문일·답변일·이번 확인일·읽은 범위·설명·적용 한계·관련 규정·영향 파일을 [출처 장부](../skills/korean-editing/references/source-ledger.md)에 기록한다. 필요한 지침·직접 쓴 수정/유지 예·`CHANGELOG.md`를 함께 고친다. 질문자 개인정보·상담 전문은 저장하지 않는다.

## 검토와 병합

작성 담당과 다른 검토자가 출처 귀속, 규정·상담·편집 선택의 구분, 의미·조건·예외와 허용형 보존을 확인한다. 행동 지침이 달라졌다면 기존 [평가 절차](../evaluations/protocol.md)에 따라 입력·기준을 먼저 정하고, 해당 판본으로 새로 수행한 교정 과제를 독립적으로 검토한다. 소수 합성 과제의 결과를 일반 효과로 확대하지 않는다.

최종 후보에서 현재 `CLAUDE.md`의 검증을 실행한다. 이 절차를 추가한 시점의 명령은 다음과 같다.

```bash
uv sync --locked --python 3.14
uv run --locked python -m unittest discover -s tests -p 'test_*.py' -v
uv run --locked python tests/skill_structure_test.py
uv run --locked python tests/source_traceability_test.py
bash tests/public_hygiene_test.sh
git diff --check
```

스킬 배포 파일이 바뀌면 `uv run --locked python scripts/package_skills.py --output <임시-출력-경로>`로 두 패키지를 확인하고 결과물을 커밋하지 않는다. 구조·ID 추적 검사는 출처 내용의 정확성이나 한국어 품질을 판정하지 않으므로 원문 대조와 독립 내용 검토를 함께 남긴다.

PR에는 보완 이유, 원문 URL·날짜, 실제 변경, 검사 명령·결과, 적용 판본과 남은 한계를 적는다. 현재 head에 대한 실제 리뷰의 유효 지적을 해결하고 적용되는 검사를 통과한 뒤, 예상 head SHA를 지정해 일반 `merge`를 실행한다. 병합 직전에 head·base와 새 리뷰를 재조회한다. `queued`, `pending`, 호출 한도, `skipped`와 `neutral`은 검사·내용 리뷰 완료를 뜻하지 않는다. 내용 변경 뒤에는 이전 판본의 리뷰·검증을 그대로 승계하지 않는다.

병합 후 PR의 `merged` 상태·병합 SHA와 `main`의 실제 파일 반영을 확인한다. 보호 우회·자가 승인·강제 push·빈 push·단순 PR 닫기로 완료 처리하지 않는다. 대기 중인 검사는 결과를 기다리되, 원인 변경 없는 반복 실행이나 리뷰 요청을 늘리지 않는다. 다음 실행이 이어갈 PR·head·미해결 사항을 남긴다.

## 기록과 알림

정본 지침·출처·평가·저장소 계획은 이 저장소에 둔다. 외부 기억에는 승인 범위·일정·결과 링크와 필요한 상태만 요약하고 코드를 복제하지 않는다. 새 근거로 달라진 판단, 잘못된 출처의 정정, 검증된 병합 또는 사용자 조치가 필요한 문제가 있을 때 결과를 알린다. 실질적 변화가 없으면 규칙 추가·빈 커밋·반복 알림을 만들지 않는다.

회차 기록에는 확인일, 기준 SHA, 조회 범위와 실패 범위, 채택·유지·보류 이유, 검증 명령·결과, 리뷰·병합 상태와 다음 재개 지점을 남긴다. 이전 실행의 날짜·SHA·대기 상태는 당시 관찰로 보존한다.
