## 에이전트 혼합과 독립성

[Mixture-of-Agents 원 논문](https://arxiv.org/abs/2406.04692)은 여러 에이전트의 제안을 다음 계층에서 결합하는 방법을 설명한다. 이번에는 이 결합 원리를 제품 개발에 적용한다. 원 논문의 모델 조합이나 벤치마크 성능을 재현했다고 주장하지 않는다. 하위 에이전트는 동일한 기본 모델을 상속할 수 있으므로 서로 다른 모델을 사용했다고 쓰지 않는다.

1. 제안 계층: 한국어 원문 조사, APA 원문 조사, 제품·Gap 분석을 서로 다른 문맥에서 수행한다.
2. 통합 계층: 리드가 실제 출처와 파일을 재확인한 뒤 공통 제약을 지키는 최소 수정만 적용한다.
3. 실행 계층: 패키징 구현과 평가 설계는 서로 다른 파일을 소유한다. 평가 실행자는 기준·모범답안을 읽지 않는다.
4. 검증 계층: 새 채점자는 입력·기준·출력으로 판정하되 초안 작성자의 정답이나 이전 채점 결과를 받지 않는다. 문맥 분리는 파일 접근 통제를 보장하지 않으므로 접근 범위는 지시·자기보고·산출물 해시로 기록하고 한계를 명시한다.

## 이번 작업 밖의 Gate

기본 브랜치 보호 복구, 정확한 원격 head의 hosted CI·비작성자 승인·merge, 조직의 라이선스 결정, immutable release, 실제 팀 dogfood는 기존 Gap으로 남긴다. 로컬 패키징은 preview이며 설치 시험을 통과해도 공식 배포나 전체 APA 적합성 인증이 아니다. 연구 원고·참여자 자료·소장 원문 전문은 넣지 않는다.
