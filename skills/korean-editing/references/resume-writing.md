# 이력서와 경력기술서

채용 공고와 실제 경력 자료를 연결해 지원자의 적합성을 설명한다. 한국어 의미 보존 조건을 먼저 적용하고, 제출처의 지정 양식·항목·분량을 확인한다. 이력서는 경력과 적합성을, 경력기술서는 프로젝트의 역할·행동·결과를, 자기소개서는 지원 이유와 경험에서 형성한 판단을 설명한다. 연구 실적을 폭넓게 싣는 학술 CV도 이들과 구분한다.

## 근거와 적용 범위

Harvard의 직무 맞춤·사실 중심·읽기 쉬운 배열 권고(W-CV1), MIT의 프로젝트·행동·결과 구성(W-CV2), Harvard의 실제 경력자 예시(W-CV4)를 참고한다. 토스의 LLM PM 채용 안내(W-CV5)와 Robert Walters의 IT 이력서 안내(W-CV6)는 국내 직무 설명의 참고 자료이며, 다른 회사의 필수 요건을 대신하지 않는다.

비생성형 글쓰기 보조 실험(W-CV3), 경력 제시 방식의 현장실험(W-CV7), 이력서 내용과 적합성 판단의 관찰연구(W-CV8)는 서로 다른 개입·대상·결과를 다룬다. 특정 문장 공식·분량·한국어 팀장 채용의 효과로 일반화하지 않는다. 아래 경력 중심 설정, 근거 대조, 압축과 기여 구분은 E1 편집 절차다. 서지·열람 범위는 [출처 장부](source-ledger.md)에 둔다.

## 작성 순서

1. **제출할 문서와 요구를 정한다.** 이력서·상세 경력기술서·자기소개서·별도 후보자 양식 중 실제 요구된 문서를 확인한다. 공고의 필수 요건, 수행 업무, 우대 요건에 대응하는 실제 경험을 작업 노트에서 연결한다. 공고가 없으면 제공된 목표 직무로 정리하되 특정 회사의 요구를 만들지 않는다.
2. **쓸 수 있는 사실을 확정한다.** 직장·직급·역할·기간·학위·자격·프로젝트·본인 행동·팀 결과·근거를 대조한다. 사용자가 이번 작성에서 명시적으로 바로잡은 사실은 반영하고, 오래된 초안·기억으로 되돌리지 않는다. 해소되지 않은 충돌은 원자료나 의뢰자에게 확인하고 유리한 값을 고르지 않는다. 학위 과정과 취득, 복수전공과 복수 학위, 기획과 구현, 참여와 총괄, 시험 운영과 정식 도입을 구별한다. 연락처와 비공개 자료는 공개 예문·평가 기록으로 옮기지 않는다.
3. **경력의 중심을 잡는다.** 확인된 경력의 출발점, 현재의 전문 영역, 반복해서 맡아 온 문제를 한 흐름으로 정리한다. 공고에 맞는 경험을 고르되 지원자를 다른 직군으로 바꾸거나 새 직함을 만들지 않는다. 공식 직급, 조직 내 역할, 프로젝트 책임을 각각 표시한다. 초기 경력이 현재 전문성을 설명하거나 지원 요건의 판단에 필요하면 남긴다.
4. **요약과 본문의 역할을 나눈다.** 상단에는 전문 영역과 이를 보여 주는 경험을 짧게 쓰고, 곧바로 경력 근거를 배치한다. 회사·재직 기간 아래에 프로젝트·수행 기간·역할과 기여를 두는 구성 등을 선택한다. 요약·핵심 역량·경력 소개에서 같은 문장을 반복하지 않는다. 경력은 역순 등 일관된 순서로 정리하고, 같은 시기의 프로젝트는 구분한다. 학교·연구·프리랜서·기업 재직의 겹친 기간을 합산해 총경력을 늘리지 않는다.
5. **경험을 행동과 확인된 결과로 쓴다.** 무엇을 해결하려 했는지, 본인이 무엇을 했는지, 어떤 산출물·결과가 확인되는지 연결한다. 맥락이 없으면 문제나 사업 효과를 발명해 형식을 채우지 않는다. `정의했다`, `분석했다`, `조율했다`, `개발했다`, `검수했다` 중 실제 책임에 맞는 서술어를 고른다. 한국어에서는 모든 항목의 첫 단어를 동사로 강제하지 않는다. 한 항목에는 같은 과제의 관련된 사실을 묶고, 새로운 인과관계가 생기지 않는지 확인한다.
6. **성과와 수치를 대조한다.** 전후 값·기간·표본·분모·단위를 확인한다. 비율 차이는 `%p`, 상대 변화는 `%`로 구별한다. 팀 성과는 팀 성과로 쓰며, 확인된 개인 기여와 이어 적는다. 수치가 없으면 산출물·적용 범위·업무 규모·확인된 정성 피드백을 사용한다. 아래 근거 구분에 따라 실제 성과를 살리되, 매출·절감액·효율 개선율·기여율을 추정해 채우지 않는다.
7. **지원 동기를 경험과 연결한다.** 자기소개서를 요구받았으면 지원 이유, 그 판단을 형성한 실제 경험, 앞으로 기여하려는 방향을 연결한다. 이력서의 모든 항목을 문장형으로 반복하지 않는다. 저자의 가치관과 경험에서 얻은 교훈은 저자의 관점으로 쓰고, [문장의 의미와 목소리 대조](engaging-sentences.md)에 따라 논점과 강조를 보존한다. 이미 달성한 조직 성과나 보편 법칙으로 바꾸지 않는다. 입사 후 계획은 미래의 행동으로 표현한다.
8. **압축과 제출본을 검증한다.** 아래 압축 순서와 제출 전 대조를 적용한다. 채용처의 분량·양식이 우선이며, 고정된 쪽수·심사 시간·ATS 점수나 통과를 약속하지 않는다. 문서 파일은 [조판과 판본 대조](report-layout-verification.md)의 공통 항목을 적용해 마지막 수정 뒤 모든 쪽의 실제 렌더와 텍스트 추출 순서를 확인한다. 표가 없는 문서에는 표 전용 항목을 적용하지 않는다.

## 어떤 근거를 어떤 결과로 쓸 것인가

| 확인된 자료 | 서술할 수 있는 기여 | 추가 근거가 필요한 주장 |
| --- | --- | --- |
| 수요별 비용 계산표를 작성함 | 비용 시나리오와 비교 자료 작성 | 운영비를 실제로 절감함 |
| 본인이 요구사항·검수 기준을 정의하고 개발팀이 구현함 | 본인의 기획·검수와 개발팀의 구현을 구분 | 본인이 전체 기능을 직접 개발함 |
| 팀 개선본에 대해 일부 사용자가 읽기 쉽다고 응답함 | 해당 사용자·대상·내용에 한정한 정성 평가 | 전체 사용자의 생산성 향상·정착률 증가 |
| 특정 기능의 호출 수나 접속 수를 집계함 | 그 기능의 사용 규모 또는 추이 | 업무 품질·처리시간·수익 개선 |
| 연구 과제의 자료 분석에 참여함 | 분석한 대상·방법·산출물과 참여 범위 | 연구 전체 총괄·제품 출시 |

이 표는 조사와 서술 판단용이다. 완성 이력서의 모든 항목에 `효과 미측정`, `개인 기여율 미산출` 같은 주석을 붙이지 않는다. 검증된 행동·산출물·결과를 적정 범위로 쓰면 된다. 결과를 이해하는 데 필요한 파일럿 범위·기간·추정 조건은 남긴다. 수치화된 성과나 리딩 책임이 확인되면 분명히 제시하며 불필요하게 약화하지 않는다.

## 문서별로 압축하는 법

분량 목표는 제출 조건과 경력의 관련성으로 정한다. 경력자 예시가 두 쪽이라는 이유로 모든 이력서를 두 쪽에 맞추지 않는다. 분량을 줄이기 전, 공고의 필수 요건과 지원자의 강점을 보여 주는 근거가 어느 항목에 있는지 확인한다.

1. 같은 소개·역량·프로젝트 설명이 반복된 곳을 먼저 합친다. 요약에서는 핵심을 선택하고 본문에서는 행동과 근거를 자세히 쓴다.
2. 관련성이 낮은 세부 사항과 내부 관리용 설명을 줄인다. 최신 경력만 남기느라 초기의 관련 전문 경력이나 실무 리딩 경험을 지우지 않는다.
3. 남길 항목은 행위자·역할·단계·기간·규모와 연결해 쓴다. `기획 참여`를 `총괄`, `박사과정 수료`를 `박사`로 줄이지 않는다. 서로 다른 시기의 일을 한 프로젝트에 합치지 않는다.
4. 이력서의 주요 경험을 자기소개서에서 다시 사용할 때는 사실을 맞추고, 선택한 이유·판단·배운 점을 설명한다. 계획을 과거 실적으로 바꾸거나 회사별 이직 이유를 섞지 않는다.
5. 본문과 약어를 읽어 본다. 독자가 역할을 이해해야 하는 약어는 첫 사용에 풀고 정확한 기술명은 유지한다. 글자 크기·여백을 과도하게 줄여 페이지 수만 맞추지 않는다. 핵심 근거가 분량을 넘으면 제출처가 허용하는 상세 경력기술서·포트폴리오로 분리한다.

연봉 등 별도 양식은 이력서의 전문성 소개와 목적이 다르다. 요청된 경우 기준 연도, 계약액·실제 수령액, 기본급·변동 보상·퇴직급여, 세전·세후 여부를 원자료대로 구분한다. 서로 다른 기준의 금액을 같은 값으로 취급하지 않는다. 지급 조건·기간·구성 항목이 확인되지 않은 금액은 추정해 채우지 않는다. 확인된 산식으로 환산할 때는 계산값임을 밝히고 기준을 함께 남긴다. 희망 조건은 현재 보상과 별도로 쓴다.

## 직접 만든 가상 예문

아래 자료와 문장은 실제 지원자의 경력이 아니다. 구조와 판단만 참고하고 인물·기간·수치를 재사용하지 않는다.

### 행동과 산출물

- 자료: 3명 팀에서 본인이 현업 15명을 인터뷰하고 문의 분류 기준 30개를 정리했다. 검수 회의 2회를 조율했다. 처리 시간과 비용 효과는 측정하지 않았다.
- 초안: `뛰어난 소통 능력으로 업무 효율을 크게 개선했습니다.`
- 수정: `현업 15명을 인터뷰하고 문의 분류 기준 30개를 정리했으며, 3명 팀의 검수 회의 2회를 조율했습니다.`

수정문은 행동·범위·산출물을 보여 준다. 자료에 없는 효율 개선이나 인터뷰와 분류 기준 사이의 인과를 덧붙이지 않는다.

### 개인의 기여와 팀 결과

- 자료: 본인은 검색 화면의 오류를 분류하고 수정 요구사항을 작성했다. 동료가 이를 구현했다. 시범 사용 부서의 담당자는 개선된 화면에서 필요한 항목을 찾기 쉬워졌다고 평가했다.
- 수정: `검색 화면의 오류를 분류하고 수정 요구사항을 작성했습니다. 동료가 이를 구현했으며, 시범 사용 부서의 담당자는 개선된 화면에서 필요한 항목을 찾기 쉬워졌다고 평가했습니다.`

개인의 요구사항 작성과 팀 결과를 함께 보여 준다. 이를 `검색 시스템을 직접 개발해 전사 업무 효율을 높였다`로 바꾸면 구현 주체·적용 범위·효과가 모두 달라진다.

### 경험에서 얻은 교훈과 앞으로의 계획

- 자료: 작성자는 교육 운영 중 수강 횟수만으로 학습자의 업무 수행 변화를 알기 어렵다고 느꼈다. 다음 직장에서는 과제 수행과 현업 피드백도 살피고 싶다.
- 수정: `교육을 운영하며 수강 횟수만으로는 학습자의 업무 수행 변화를 알기 어렵다고 느꼈습니다. 앞으로는 과제 수행과 현업 피드백도 살피는 교육 운영을 추진하고자 합니다.`

저자의 판단과 계획으로 쓴다. `기존 교육은 효과가 없었다`, `성과 중심 교육 체계를 정착시켰다`처럼 대상 전체의 결론이나 완료 실적으로 바꾸지 않는다.

## 제출 전 대조

- 상단 요약의 전문성을 본문의 어느 경험이 뒷받침하는가? 지원 직무와 맞추면서 원래의 경력 정체성을 바꾸지 않았는가?
- 면접에서 본인의 행동과 산출물을 설명하고, 수치의 출처·산식을 제시할 수 있는가?
- 팀 성과·개인 역할·공식 직급·프로젝트 단계·기간·학력의 범위가 원자료와 같은가?
- 압축하면서 중요한 경력이나 조건을 지우거나, 떨어진 사실을 새 인과관계로 묶지 않았는가?
- 지원 동기의 관점·교훈·미래 계획이 과거 성과로 바뀌지 않았는가? 묶음 문서 사이에 직책·기간·수치가 일치하는가?
- 최종 파일의 모든 쪽에서 제목과 본문 연결, 목록의 쪽 나눔, 연락처·날짜·글자 잘림과 과도한 밀집을 확인했는가? 텍스트 추출 순서와 링크도 확인했는가?

이력서 본문이나 수정 파일을 먼저 전달한다. 내부 근거표나 모든 조사 경위를 이력서에 붙이지 않는다. 필요한 사실을 확보하지 못한 부분은 다른 항목의 작성을 진행하면서 의뢰자에게 별도로 묻는다. 지원자의 확인 없이 경력·학력·자격을 보완하지 않는다. 렌더링이나 제출 시스템 검증을 수행하지 못했다면 확인한 범위만 설명한다.
