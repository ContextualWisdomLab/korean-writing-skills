# 비문을 실제 문장으로 고치기

문장 교정을 요청받았을 때 쓴다. 오류 이름을 붙이거나 확인 질문만 나열하는 것으로 교정을 대신하지 않는다. 뜻이 분명하면 수정문을 완성한다. 아래 절차와 예문은 [출처 장부](source-ledger.md)의 K1 pp.11–12, A-JANG1999 §2.1.2·§2.2.1–3을 참고한 **편집 판단**이다. 맞춤법의 새 조항이나 원문 예문의 복제가 아니다.

## 진단에서 수정까지

1. **문장의 뼈대를 읽는다.** 수식절을 잠시 괄호로 묶고 ‘누가/무엇이—무엇을/누구에게—어찌한다’를 찾는다. 생략된 성분은 앞 문맥에서 이어지는지 확인한다. 모든 문장에 표면 주어를 넣지는 않는다.
2. **깨진 관계를 특정한다.** 주어–서술어, 목적어–서술어, 조사–서술어, 관형절–수식 대상, 병렬 항목–공유 서술어를 각각 대조한다. ‘어색하다’ 대신 어떤 말끼리 결합하지 않는지 확인한다. 화제 조사 ‘은/는’이 붙었다는 이유만으로 그 말을 주어로 확정하지 않는다.
3. **뜻이 정해져 있으면 고친다.** 조사·어미 수정, 문맥에 명시된 성분 복원, 병렬 구조 정리, 절의 재배치 중 필요한 방법을 고른다. 한 글자 수정으로 해결되지 않으면 절이나 문장을 다시 구성한다. 수정량이 적다는 이유로 남은 비문을 채택하지 않는다.
4. **뜻을 새로 정해야 하면 그 부분만 묻는다.** 문맥에 없는 행위자·대상·원인·비교 기준을 채우거나 부정·수식 범위를 하나로 정해야 하는 경우다. 원문을 남기고 구체적으로 묻는다. 같은 입력의 다른 명백한 오류는 먼저 고친다. 가능한 표현이 여러 개라는 사실만으로 보류하지 않는다.
5. **고친 문장만 다시 읽는다.** 원문을 보아야 이해되는 문장이 아닌지, 호응이 끝까지 맞는지 확인한다. 그다음 원문과 대조해 행위자·수치·조건·부정·시제·추정·당위·인용의 귀속을 확인한다. 뜻은 지켰어도 비문이 남으면 교정 완료가 아니다.

## 유형별 수리와 반례

모두 직접 만든 가상 예문이다. 단어를 외워 자동 치환하지 않는다.

| 유형 | 원문 → 수정문 | 보존할 내용과 경계 |
| --- | --- | --- |
| 주어와 서술어의 틀 불일치 | `이번 검토의 목적은 오류의 원인을 찾고자 한다.` → `이번 검토의 목적은 오류의 원인을 찾는 것이다.` | 목적을 실제 원인 발견 사실로 바꾸지 않는다. 필요한 명사절은 남긴다. |
| 주장 내용을 받는 절 누락 | `보고서의 결론은 야간 상담을 한 달 더 운영할 필요가 있다.` → `보고서의 결론은 야간 상담을 한 달 더 운영할 필요가 있다는 것이다.` | 한 달 더·필요성과 보고서에 귀속된 결론을 보존한다. |
| 조사와 피동 서술어의 불일치 | `최종 후보 3명을 선정되었다.` → `최종 후보 3명이 선정되었다.` | 누가 선정했는지 만들지 않는다. 피동 자체를 없애려 하지 않는다. |
| 관형절이 받는 말 누락 | 앞 문맥에 추가 제출 대상이 서류라고 명시됨. `담당자는 신청인이 추가로 제출해야 하는 안내했다.` → `담당자는 신청인이 추가로 제출해야 하는 서류를 안내했다.` | 문맥의 ‘서류’만 복원한다. 구체 서류명·기한은 추가하지 않는다. 문맥이 없으면 같은 복원을 확정하지 않는다. |
| 병렬 항목의 구조 불일치 | `교육 목표는 기록을 정확히 작성하고 자료의 보존이다.` → `교육 목표는 기록을 정확히 작성하고 자료를 보존하는 것이다.` | 목표의 두 항목을 유지한다. 작성·보존을 이미 수행했다고 바꾸지 않는다. 명사형 병렬 대안도 가능하다. |
| 공유 서술어와 일부 목적어의 불일치 | `담당자는 안내문을 게시하고 문의에 답했다`라는 뜻이 문맥에 명시됨. `담당자는 안내문과 문의에 답했다.` → `담당자는 안내문을 게시하고 문의에 답했다.` | ‘게시’의 근거가 없으면 상상해서 보충하지 않는다. 항목마다 서술어를 대입해 누락을 찾는다. |
| 중첩된 절의 연결 실패 | `담당자는 누락이 발견되면 재검토한다는 방침을 신청인에게 알렸다는 사실을 기록했다는 것이다라고 설명했다.` → `담당자는 누락이 발견되면 재검토한다는 방침을 신청인에게 알렸다는 사실을 기록했다고 설명했다.` | 조건부 재검토·알림·기록·설명의 관계를 남긴다. 실제 누락이 발견됐다거나 재검토가 끝났다는 문장으로 나누지 않는다. |
| 확인된 수식 대상의 잘못된 위치 | 작성자가 ‘꼼꼼하게’는 읽는 방식이라고 확인함. `심사자는 꼼꼼하게 수정한 원고를 읽었다.` → `심사자는 수정한 원고를 꼼꼼하게 읽었다.` | 확인이 없으면 원문도 가능한 문장이다. 원고 수정자를 심사자로 만들어 넣지 않는다. |

## 고치지 않아야 하는 문장

- `검토자는 첨부 파일을 열었다. 먼저 표의 수치를 확인했다.`: 앞 문맥에서 이어지는 주어 생략이다. 둘째 문장에 주어가 없다는 이유만으로 비문이라 하지 않는다(P-SONG2013의 담화 속 생략 주어 설명을 참고한 편집 판단).
- `이번 점검의 범위는 접근 권한의 확인과 오류 기록의 보존이다.`: 명사형 병렬이 호응한다. 동사형으로 바꾸며 수행 사실을 추가하지 않는다(K1 p.12).
- `기록이 삭제되었다.`: 행위자를 모르는 피동문도 온전하다. ‘담당자가 삭제했다’로 바꾸지 않는다.
- `모든 신청자가 동의한 것은 아니다.`: 부정 범위를 보존한다. ‘아무도 동의하지 않았다’로 단순화하지 않는다.

## 질문이 필요한 문장

- `검토를 마친 표와 부록을 공개했다.`: 검토 완료가 표만인지 둘 다인지 문맥에 없으면 원문을 두고 그 범위를 묻는다. 질문 없이 ‘검토를 마친 표와 검토를 마친 부록’으로 풀지 않는다.
- `통계 담당자는 기준 모형과 비교했다.`만 주어졌다면: 무엇을 비교했는지 묻는다. 비교 대상을 찾지 못했다는 것과 문법적 생략이 항상 금지된다는 것은 다르다.

질문은 교정문 밖에 둔다. **명백한 오류의 수정문 → 필요한 경우 짧은 수정 이유 → 남은 뜻 확인 질문** 순으로 전달한다. 맞춤법만 요청받았다면 문장 재작성은 적용하지 않고 별도 제안으로 구분한다.
