# 업무 보고서의 조사와 교정

## 적용 범위

업무·진척·결과 보고서를 작성하거나 내용까지 교정할 때 적용한다. 기존 스킬의 독자·장르·수정 범위 판단과 의미 보존 조건을 따른다. 맞춤법만 의뢰받았다면 조사나 구조 개편으로 범위를 넓히지 않는다. 아래 절차는 E1 편집 판단과 U1 사용자 선호이며 어문 규정이 아니다.

## 작성 전에 확인할 일

요청된 항목의 원자료와 실행 결과를 읽고, 필요한 사실은 담당자에게 확인한다. 에이전트가 더 조사할 일은 자신의 작업 노트·할 일 관리에 기록한다. 문서 파일과 초안에는 에이전트의 확인 표지나 조사 과제 목록을 넣지 않는다. 접근 가능한 자료를 먼저 확인하고, 필요한 자료·권한을 얻지 못하면 의뢰자에게 구체적으로 요청한다. 보고의 핵심 사실을 해결할 수 없다면 납품 범위를 의뢰자와 조율한다.

결과에 내재한 불확실성과 에이전트가 덜 조사한 상태를 구별한다. 연구의 추정치·신뢰구간·설계 한계, 확인된 기능 제한·실패·위험은 보고할 내용이다. 조사 과제를 문서 밖에서 관리한다는 이유로 이러한 사실이나 원문의 필요한 부정·조건을 삭제하지 않는다.

## 내용과 문장을 고치는 순서

1. **의미를 대조한다.** 원자료와 원문의 행위자·대상·수치·시점·조건·부정·주장 강도를 확인한다. 모르는 상태를 완료·진행 중·예정으로 바꾸거나 자료에 없는 원인·담당·기한을 보태지 않는다.
2. **독자에게 필요한 순서로 정리한다.** 진척 보고에서는 실적 → 남은 작업 → 조치 계획을 기본으로 삼는다. 주어진 양식과 독자의 목적에 맞게 배열하고, 시간·절차 순서가 필요한 글은 그 순서를 유지한다. 완료된 항목에 남은 작업을 억지로 만들거나 모든 항목에 같은 설명을 반복하지 않는다.
3. **문장을 완성한다.** [문장 수리 절차](sentence-repair.md)에 따라 뜻이 분명한 호응 오류는 바로 고친다. 불필요한 확인 질문으로 교정을 대신하지 않는다. 표현을 다듬을 때는 대상·수량·기간·결과로 실적을 정확히 쓴다. 독자에게 필요하지 않은 작성 과정 해설을 덧붙이지 않는다. 특정 어미나 낱말을 일괄 금지하거나 동의어로 자동 치환하지 않는다.
4. **의미가 갈리는 부분만 묻는다.** 원문 교정에서 저자의 뜻을 새로 정해야 하면 해당 원문을 보존하고 질문은 교정문 밖에서 전달한다. 에이전트 자신의 조사 과제는 작업 노트에 둔다. 다른 명백한 오류의 교정은 계속한다.

진척률을 보고할 때는 원 계획의 작업량·단계·가중치와 실제 실적을 대조한다. 기존 산정 기준을 먼저 확인하고, 기준이 없으면 의뢰자와 산정 방식을 정한다. 항목 종결 수와 작업 진척률을 혼동하지 않으며, 근거 없는 백분율을 만들지 않는다. 확인된 대상 목록이 있는 행의 달성률은 아래 절차로 산출한다.

## 실적 표에 넣을 사실

진척·결과 보고의 표는 독자가 각 행의 실적을 숫자와 대상으로 읽을 수 있어야 한다. 아래 네 가지 중 해당 행에 적용되는 내용을 작성 전에 원자료로 확인한다. 달성률에는 집계 단위·대상 목록·달성 기준이 필요하다. 모자란 사실은 먼저 조사하고, 접근할 수 없는 핵심 자료만 의뢰자에게 요청한다. 버전 변경이나 PR 병합과 관계없는 행에 그 정보를 억지로 만들지 않는다.

1. **달성 수/전체 대상 수와 달성률.** 각 행에 집계 단위(호스트·모델·지역·작업·PR 등), 분자와 분모, 백분율, 기준 시점을 함께 쓴다. 달성률은 `달성 수 ÷ 전체 대상 수 × 100`으로 계산하고 표시 자릿수를 통일한다. 전체 대상 수가 0이면 백분율을 계산하지 않는다. 분모는 원 계획·대상 목록·담당자가 확인한 범위에서 가져오고, 실적에 맞춰 분모를 줄이지 않는다. 점검·설치·운영 적용·검증을 서로 다른 단계로 집계한다. 한 단계의 달성 수를 다음 단계의 실적으로 옮기지 않는다. 관측하지 못한 대상을 실패나 미달성 0건으로 세지 않는다. 그런 대상이 있으면 분모를 정하기 전에 먼저 확인한다. 항목 수 기준 달성률과 작업량 가중 공정률은 이름을 구별해 쓰고, 공정률은 가중치나 산정 기준이 있을 때만 쓴다.
2. **변경 전과 변경 후.** 버전 적용·설치·전환을 실적으로 쓰기 전에 기준 시점 이전의 기존 상태를 확인한다. `변경 전 → 변경 후` 값을 함께 쓰고, 이미 같은 값이었다면 적용 실적이 아니라 유지·재확인으로 쓴다. 원 계획의 목표값, 실제 적용값, 후속 빌드값을 서로 구별한다. 이력·배포 기록·담당 과업의 본문과 이후 댓글을 함께 읽고, 과업 제목에 적힌 버전 경로만으로 단정하지 않는다.
3. **대상 식별자.** `호스트 3대`, `양 호기`, `나머지 4대`처럼 수량만 쓰지 않는다. 호스트명·자원 이름·모델명·지역처럼 독자가 대상을 특정할 수 있는 식별자를 행 안이나 바로 아래 주에 쓴다. 문서 안에서 쓰는 별칭(운영 1호기 등)은 첫 사용에서 실제 이름과 대응시킨다. 같은 대상을 다른 이름으로 이중 집계하지 않았는지 대조한다. 중복 0건을 확인하지 않고 그렇게 쓰지 않는다.
4. **병합 후 후속 조치.** PR·수정의 병합은 코드 반영 단계다. 병합 후에 필요한 배포, 설정·데이터베이스 적용, 재검증, 관련 과업 종료를 PR·과업·실행 기록에서 확인하고 각각 끝났는지를 셈한다. 각 단계에서 실제 조치가 필요한 대상만 분모로 삼고, 병합 건수와 배포 호스트 수처럼 다른 단위를 섞지 않는다. 단계마다 달성 수/대상 수와 백분율을 함께 쓴다. 병합만 확인했으면 병합 실적으로만 쓰고 배포·재검증 완료를 암시하지 않는다. 후속 조치가 필요 없는 수정이면 그 근거를 확인한다.

## 채택 전 대조

기존 스킬의 **의미·자료·자연스러움·과잉 교정** 조건으로 원문과 수정본을 대조한다. 보고 내용의 누락, 주장의 과장, 필요한 불확실성·실패·위험의 삭제를 확인한다. 실적 표는 위 네 가지를 행마다 원자료와 다시 맞춘다. 분자·분모·백분율의 계산, 변경 전후 값, 대상 식별자 목록, 병합 후 단계별 건수가 원자료와 같아야 채택한다. 작성자가 아닌 검토자가 이 대조를 한 번 더 할 수 있으면 맡긴다. 조사 과제와 작성 과정 해설을 제거한 뒤에도 문장 호응과 지시 대상이 분명한지 읽는다. 맞춤법·띄어쓰기·문장 부호는 [표기 판단](orthography-decisions.md)에 따라 마지막에 점검한다.
