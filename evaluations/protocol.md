# 독립 평가 절차

담당 역할: 독립 평가 워커. 소유 범위: `evaluations/`.

## 독립성

- 평가 설계자·채점자는 작성자의 정답과 초안 `SKILL.md` 본문을 읽지 않는다. 준비 여부와 파일 해시는 확인할 수 있다.
- 실행자는 새 독립 에이전트로 둔다. 해당 스킬, 관련 근거 파일, `scenarios/blind-inputs.md`의 담당 사례만 제공한다. 루브릭, 예상 답, 작성자의 설명, 다른 실행 결과, 채점 결과는 제공하지 않는다.
- 출력은 저장소 밖 격리 작업공간에 만든다. 원본 출력과 실행 범위를 확인한 후 재현에 필요한 평가 증거만 `evaluations/runs/`에 복사한다. 공개 기록에는 로컬 절대경로나 ephemeral session/run 식별자를 남기지 않는다.
- 루브릭과 시나리오의 해시를 실행 전에 기록한다. 실행 후 기준을 바꾸어 통과시키지 않는다.

## 실행과 채점

1. 준비가 끝난 한국어·APA 스킬의 저장소 상대 경로를 확인한다. 초안이 수정 중이면 실행하지 않는다.
2. 스킬 및 참조 파일을 격리 작업공간에 복사하고 입력별 SHA-256을 기록한다. 이는 실행한 버전의 증거이며 원격 커밋 확인을 대체하지 않는다.
3. 한국어 사례 K1–K6, APA 사례 A1–A3를 사례마다 새 대화·새 context의 실행자에게 하나씩 전달한다. 한 대화에 여러 사례를 묶지 않는다. 공개 결과에는 사례 ID, 실행 역할, 입력·스킬 버전·출력 SHA-256, context 격리 여부를 기록한다. 실행자·채점자의 식별자와 세션 기록은 공개 결과에 넣지 않고 비공개 운영 기록에 보관하며, blind 수용 여부는 그 기록으로 확인한다(`runs/round-4-k7-k8/status.md`의 수용 조건). 실행자는 요청별 교정문과 이유 또는 요청된 산출물을 반환한다. 새 사실 생성이나 외부 메시지 발송은 허용하지 않는다.
4. 채점자는 원문과 실제 출력만 대조하여 [analytic-korean-editing.md](rubrics/analytic-korean-editing.md) 항목 판정과 `three-axis.md`의 세 점수, 중대 오류 여부, 짧은 근거, 통과·실패·보류를 사례별로 기록한다. 합산점수·가중치는 사용하지 않는다. 세 축 각각 2점 이상이라는 내부 수용 경계를 사용하며, 검증된 시험 절단점이라고 부르지 않는다.
5. 관찰된 실패만 수정 요청으로 전달한다. 재평가가 필요하면 수정 버전과 실행 차수를 별도로 남긴다. 첫 실패 기록을 덮어쓰지 않는다.

완료 기준: 양쪽 스킬을 대상으로 실제 블라인드 실행 1회, 모든 사례별 채점, 실행 입력·버전·출력 해시·독립성 한계 기록. 단일 실행은 일반적 효과나 작성자 대비 성능 향상을 입증하지 않는다.

근거: skill-creator의 Independent Forward-Testing 원칙을 직접 확인했다(2026-09-20). 현실적인 요청, 최소 원자료, 의도한 답 미제공, 격리 실행 원칙을 따른다. 설치 위치는 실행 환경마다 달라질 수 있으므로 공개 계약에는 로컬 설치 절대경로를 고정하지 않는다.

실행 후 보완(2026-09-20): 1회차는 분야별 묶음 실행이었고 A2에서 다른 사례의 설계가 섞인 것으로 의심되는 출력을 관찰했다. A2 단독 새 실행에서는 재현되지 않았다. 이후에는 사례마다 별도 대화에서 실행한다(3단계). 같은 대화에서 독립된 연구임을 명시하는 방식은 앞 사례의 문맥 유입을 막지 못하므로 쓰지 않는다. 이 보완은 원래 루브릭·시나리오나 최초 판정을 바꾸지 않는다. 실제 완료 상태와 잔여 의존성은 `runs/round-1-review.md`에 기록한다.

평가 문서만 소유하며 코드 탐색이 필요하지 않고 `.codegraph/`가 없었다. 초안 본문 노출을 막기 위해 저장소 전체 색인은 만들지 않는다.
