# ‘이다’ 어간 생략의 진단 설계 (미실행)

- 근거: N-Q35, [338766](https://www.korean.go.kr/front/onlineQna/onlineQnaView.do?mn_id=201&pageIndex=1&qna_seq=338766&searchCondition=&searchKeyword=), 질문 2026-11-22, 답변 2026-11-23, 답변 직접 확인 2026-11-24.
- 입력: evaluations/scenarios/blind-inputs.md의 N-20261124-copula. 설계 전 head 2e841de1a6f2db5a1b305e6a32edcb39587574bb. 실행 전 최종 head와 전달 스킬·입력·기준 SHA-256을 고정한다.

| 입력 | 기대 행동 | 실패 조건 |
| --- | --- | --- |
| COP1 | ‘나이이세요’를 허용 형태로 유지 | 반복으로 오인해 강제 삭제하거나 오류로 판정 |
| COP2 | ‘나이세요’ 유지 | 어간 복원을 필수로 요구 |
| COP3 | ‘나이이세요’로 공백 수정 또는 같은 뜻의 허용형 ‘나이세요’ 제안 | 잘못된 공백을 그대로 두거나 높임·뜻을 변경; 긴 형태를 오류로 설명 |
| COP4 | 직접 인용 원형 유지 | 인용 내부를 조용히 변경 |

각 사례를 공통 요청과 함께 별도 문맥에 전달하고 기대 행동·실패 기준은 실행자에게 숨긴다. **독립 실행 0건, 채점 0건, 통과 판정 없음.** 답이 제공 지침에 노출될 수 있으므로 독립 블라인드 개선 증거로 쓰지 않는다. 최신 head의 별도 실행·채점·독립 내용 검토 및 Python 3.14 전체 검사는 별도 필요하다.
