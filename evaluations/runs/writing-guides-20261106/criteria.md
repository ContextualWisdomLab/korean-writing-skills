# 한국어 작성 과제 독립 평가 기준

## 적용 범위

`resume-input.md`, `report-input.md`, `sentences-input.md`의 가상 자료와 기존 `three-axis.md`, `analytic-korean-editing.md`만으로 작성한 과제별 보충 기준이다. 평가 설계자는 출력물·스킬 초안·다른 실행 결과를 보지 않았다. 최종 비교에는 이 기준을 고정한 뒤 새로 실행한 익명 출력만 사용한다.

세 과제는 **신규 문안 작성**이다. 기존 교정문과의 문자열 일치, 원문과의 편집 거리, 능동문 비율, 특정 어휘·어미 사용 여부를 점수로 삼지 않는다. 정답 문안을 정하지 않으며, 의미와 적용 범위가 같은 표현·배치·문체는 인정한다. 제한된 분량 안에서 모든 메모를 나열할 필요는 없으나, 생략 때문에 역할·근거·조건을 오해하게 해서는 안 된다.

## 공통 3축과 판정

| 축 | 적용 기준 |
| --- | --- |
| 의미 보존 | 입력의 사실·수치·행위자·범위·부정·불확실성과 출력의 주장을 대조한다. 자료에 없는 성과, 인과관계, 담당 역할, 기능, 검증 결과를 사실로 추가하지 않는다. |
| 한국어 자연스러움 | 목적과 독자에 맞는 문장·문단 흐름, 호응·수식 범위·병렬, 읽기 쉬운 어휘와 표기를 평가한다. 명사화·한자어·피동 자체를 오류로 보지 않는다. |
| 과잉 교정 억제 | 작성 과제에서는 **허용된 작성 범위와 목적·형식 준수**로 적용한다. 재작성량 대신 불필요한 설명·자의적인 목적 변경·명시적 제약 무시 여부를 본다. |

점수는 원 루브릭의 0–3 수준을 유지한다. 의미 보존은 3=관련 명제와 조건을 정확히 유지, 2=핵심 유지 및 경미한 모호함·누락, 1=중요한 조건·범위·논리 변경 또는 누락, 0=사실·수치·역할 날조나 결론 뒤집기다. 자연스러움은 3=읽기 쉽고 일관됨, 2=한두 곳 어색하나 이해 가능, 1=여러 곳에서 흐름 단절, 0=요청한 한국어 글로 기능하지 못함이다. 세 번째 축은 3=과제에 필요한 작성과 형식을 충족, 2=경미한 불필요한 추가가 있으나 용도 유지, 1=획일적인 문체 강제나 과도한 개입, 0=목적 훼손 또는 명시적 제약 무시다.

각 축 2점 이상이며 중대 오류가 없어야 통과한다. 평균·합계로 상쇄하지 않는다. 무근거 인과·효과 확정, 수치 변조, 역할·제품 기능·검증 결과 날조는 중대 오류로 기록한다. 형식 오류를 사실 오류로 자동 전환하지 않고 축별 근거를 남긴다. 미실행·빈 응답·접근 범위 위반은 보류한다.

## 1. 이력서

- **형식·용도:** 상단 요약 2문장과 핵심 경험 3개, 완성 문안만 제시한다. 제목·번호·글머리표는 허용한다. 채용 공고의 문제 정의, PoC 성과 검증, 부서 간 조율과 실제 경험의 연결을 읽을 수 있어야 한다. 특정 역량 표현이나 항목 순서는 요구하지 않는다.
- **개인 역할:** 현업 담당자 8명 인터뷰, 평가셋 120건 구성, 검색 성공률 지표 정의, 개발팀·현업팀 평가 기준 협의는 개인 경험으로 쓸 수 있다. 모델 개발·프로젝트 전체 총괄·개인 기여율·단독 성과를 부여하면 안 된다. 기간·팀 규모를 쓰면 2024년 4월~2025년 3월, 4명과 맞아야 한다.
- **성과 귀속·범위:** 검색 성공률 62%→74%는 같은 평가셋·기준에서 얻은 팀 결과다. 이를 쓰면 개인 성과와 팀 결과를 혼동시키지 않아야 한다. 차이는 12%p이며, 상대 증가율을 쓰면 약 19.35%로 구분해야 한다. 숫자 자체를 생략해도 부정확한 주장으로 대체하지 않으면 된다.
- **증거 한계:** 개인 활동이 개선을 일으켰다고 확정하거나 통계적 유의성·비용 절감·매출 효과를 만들지 않는다. 사용·배포 현황을 언급하면 1개 부서 사용, 전사 배포 전이라는 범위를 유지한다. 통제집단 부재 등 모든 제한을 문장으로 나열할 의무는 없지만, 검증된 인과·효과가 있는 듯 쓰면 안 된다.

## 2. 의사결정 보고서

- **형식·용도:** 첫 문장 또는 첫 문단에서 권고와 비용 영향을 파악할 수 있어야 한다. 현행 유지·A 도입·B 추가 검증 후 도입을 비교하고 다음 조치를 포함한다. 조사 과정 설명은 제외한다. 특정 권고 문구를 요구하지 않으며, 선택지·비용 제약·검증 상태와 양립하는 권고를 인정한다.
- **분량:** 전체 제출 문자열을 700자 이내로 제한한다. CRLF/CR을 LF로 바꾼 뒤 유니코드 코드 포인트를 센다. 공백·줄바꿈·문장 부호·마크다운 표시를 포함하며, 다른 정규화나 앞뒤 공백 제거는 하지 않는다. 이 계산법은 이번 평가의 운영 기준이다.
- **비용 대조:** 아래 값은 검산 기준이며 모든 파생 수치를 반드시 출력할 필요는 없다. 원수치와 비교 결론을 정확히 전달하는 방식도 인정한다.

| 선택지·기준 | 검산값 |
| --- | --- |
| 현행 | 월 900만원; 과거 도입비 미제공 |
| 허용 한도 | 월 운영비 최대 15% 증가, 월 1,035만원 |
| A | 월 1,080~1,170만원, 월 +180~270만원·+20~30%, 한도 초과; 도입비 1,800만원 |
| B | 월 990만원, 월 +90만원·+10%, 한도 이내; 도입비 700만원 별도 승인 |

- **비교 조건:** 운영비는 같은 사용량·서비스 범위·세금 기준이다. 월 운영비와 일회성 도입비를 혼합하여 15% 기준을 판정하지 않는다. 현행의 과거 도입비를 0원으로 만들거나, 제공되지 않은 절감액·ROI·회수기간을 주장하지 않는다. 추가 기간 합계를 계산하면 기간과 계산 조건을 명시한다.
- **품질·불확실성:** A의 기대 품질 개선은 미시험이다. B는 2일·300건 파일럿에서 저하가 관찰되지 않았을 뿐 장기·성수기 품질을 확인하지 않았다. B의 동등성·무위험·장기 성능을 확정하거나 시험 완료로 바꾸면 안 된다. 표본·기간을 생략하더라도 제한된 파일럿 결과라는 성격과 추가 검증 필요성을 유지한다.
- **다음 조치·승인:** 운영팀이 11월 15일까지 B의 성수기 조건을 시험할 수 있다는 일정·담당 범위와, 추가 시험 승인 및 B 도입비 검토 요청이 드러나야 한다. 아직 완료하지 않은 시험이나 승인 상태를 완료로 쓰지 않는다. 제안하는 후속 조치는 제안임을 구분한다.

## 3. 지출 앱 문구

- **형식·용도:** 독립적으로 사용할 수 있는 3개 안을 제시하고, 각 안은 제목 1문장과 설명 1문장으로 구성한다. 문장 여부는 마침표 개수만으로 판정하지 않는다. 문구 외 해설을 넣지 않는다. 독자에게 자연스럽게 말을 걸면서 각 안의 표현이나 접근이 구별되어야 한다. 기능명·요일처럼 필요한 단어의 반복은 중복 문구로 보지 않는다.
- **기능·조건:** 각 안을 제목과 설명의 한 쌍으로 읽어, 금융계좌 연결이 필요하며 연결한 계좌의 지난주 지출을 월요일마다 모아 보여준다는 조건·대상·기간·주기가 전달되는지 확인한다. 두 문장 사이에서 정보를 나누는 것은 허용한다. 계좌 연결을 요청하는 문장도 조건 전달로 인정한다. 연결하지 않은 계좌까지 수집하거나 실시간으로 처리하는 기능을 암시하면 안 된다.
- **효과·표현:** 매력적인 표현과 이용 권유는 허용하지만 자동 절약·투자 기능, 측정된 절약 효과, 경제적 이익 보장, 제공되지 않은 분석 기능을 만들지 않는다. 원문 명사형 문구를 보존할 필요는 없고, 새로운 비유나 질문도 제품 사실과 충돌하지 않으면 인정한다.

## 평가 기록과 고정

평가자는 익명 출력 ID와 과제명, 각 확인 사항의 충족/부분 충족/위반/해당 없음, 짧은 입력–출력 대조 근거, 3축 점수, 중대 오류, 통과/실패/보류를 기록한다. 선택적으로 쓸 수 있는 메모를 생략한 경우에만 해당 없음을 쓴다. 필수 형식·조건은 해당 없음으로 처리하지 않는다. 보고서는 실제 문자 수와 제시된 계산의 검산 결과도 기록한다.

출력 확인 뒤 새 기준을 추가하거나 최초 판정을 덮어쓰지 않는다. 해석 차이는 별도로 기록한다. 본 기준은 기존 프로젝트 잠정 루브릭을 세 작성 과제에 적용한 것이며, 공적 어문 규정이나 타당화된 시험·채점자 신뢰도 검증을 뜻하지 않는다. 원 루브릭에 연결된 외부 문헌은 이 작업에서 추가로 열람하지 않았다.
