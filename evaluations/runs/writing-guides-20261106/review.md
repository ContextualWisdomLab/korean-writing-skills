# 이력서·보고서·문장 작성 지침 보강 평가

## 비교 결과

가상의 세 유형을 각각 새 문맥에서 작성하고 판본 이름을 가려 채점했다. 기존판은 2/3, 보강 v2는 3/3이 고정 기준을 충족했다. 이는 유형별 한 사례·판본별 한 실행의 텍스트 점검이며 일반적 성능 향상이나 실제 채용·업무 효과를 입증하지 않는다.

점수 순서는 의미 보존 / 한국어 자연스러움 / 작성 범위·형식 준수다. 세 축이 각각 2점 이상이고 중대 오류가 없어야 통과한다. 합계로 실패를 상쇄하지 않았다.

| 과제 | 기존판 출력·점수 | 보강 v2 출력·점수 | 판본을 가린 평가자의 비교 |
| --- | --- | --- | --- |
| 이력서 | [B](resume-B.md), 3 / 3 / 3, 통과 | [A](resume-A.md), 3 / 3 / 3, 통과 | 동률. 개인 역할·팀 성과·기간·현재 사용 범위 보존 |
| 의사결정 보고서 | [A](report-A.md), 3 / 3 / 3, 통과 | [B](report-B.md), 3 / 3 / 3, 통과 | 둘 다 통과. 보강판의 승인 조건·제안 상태 표현을 선호 |
| 지출 앱 문구 | [B](sentences-B.md), 1 / 3 / 3, 실패 | [A](sentences-A.md), 3 / 3 / 3, 통과 | 기존판 둘째 안의 `한 주 동안`은 집계 기간이 지난주임을 명시하지 못함 |

보고서의 전체 문자열은 기존판 563자, 보강 v2 566자로 각각 700자 이내다. 같은 조건의 월 운영비 비교, A의 20–30% 증가와 B의 10% 증가, 별도 도입비, 파일럿 관찰과 장기·성수기 미검증 상태를 모두 보존했다. 문구의 각 안은 독립적으로 사용할 수 있어야 하므로 다른 안에 있는 기간 정보로 누락을 보충하지 않았다. [최초 독립 채점](blind-grading.md)과 [항목별 JSON](blind-grading.json)을 수정 없이 보존한다.

## 최종 보고서 지침의 재점검

GitHub 검토 후 보고서 예문을 고친 v3로 [보고서 한 건을 새로 작성](regression-v3-report.md)했다. 다른 새 평가자가 같은 기준으로 점검한 결과 의미·자연스러움·범위가 각각 3점이며 중대 오류 없이 통과했다. 전체 문자열은 570자로 700자 이내이고, 비용 증감·한도 판정·별도 도입비·품질 검증 한계·승인 후 시험 조건이 보존되었다. [별도 독립 판정](regression-v3-grading.md)과 [항목별 JSON](regression-v3-grading.json)을 함께 기록한다.

이 재점검은 기존 보고서 입력을 다시 사용한 한 사례다. v2의 세 입력 비교와 합쳐 네 개의 독립 사례로 세지 않는다. 채점자의 `report-output.md`는 공개 기록의 `regression-v3-report.md`와 같은 파일이며 대응 해시는 manifest에 있다.

## 판본과 독립성

- 기존판: `f00ab66634d6b0d1496b7ff4d724e0dc0168927b`의 한국어 스킬.
- 보강 v2: `4506bf3ccd14df046e6c5ecf2423b615736be825`의 한국어 스킬. 첫 독립 내용 검토가 발견한 이력서 예문의 근거 관계를 고친 판본이다.
- 실행 스냅샷에는 해당 스킬과 참고 파일만 넣고 평가 기록이 담긴 `references/validation.md`를 제외했다.
- 시나리오는 작성 담당자가 만들었다. 별도 설계자가 입력 3개와 기존 루브릭 2개만 읽고 [과제별 기준](criteria.md)을 동결했다. 스킬 초안·실행 출력은 보지 않았다.
- 최종 비교 실행 6개는 그 기준을 고정한 뒤 각각 새 문맥에서 수행했다. 실행자는 스킬과 담당 입력만 제공받았고, 기준·예상 답·다른 출력은 제공받지 않았다.
- 별도 채점자는 기준·입력·익명 출력 6개만 읽었다. 판본 매핑과 스킬 초안은 읽지 않았다. 실행자에게는 스냅샷 이름이 보였으므로 실행자까지 판본을 가린 평가로 표현하지 않는다.
- 접근 범위는 지시와 자기보고에 근거한다. 운영체제로 파일 접근을 차단한 실험은 아니다. 단일 평가자의 판정이며 채점자 일치도를 검증하지 않았다.

기준·입력·스냅샷·출력의 SHA-256과 판본 매핑은 [manifest](manifest.json), [기준 동결](criteria-freeze.json), [v2 스냅샷](comparison-v2-freeze.json)에 있다. 기준 파일 끝의 루브릭 경로는 격리 작업공간에서 사용한 상대 위치다. 공개 저장소의 원본은 [3축 루브릭](../../rubrics/three-axis.md)과 [분석적 루브릭](../../rubrics/analytic-korean-editing.md)이며 manifest에 대응 해시를 적었다.

## 이전 출력과 검토 이력

기준 동결 전에 만든 탐색 출력 3개는 `exploratory-*.md`로 보존하며 위 통과 수에 넣지 않는다. 최초 후보 v1로 시작한 이력서 출력도 [candidate-v1-resume.md](candidate-v1-resume.md)에 보존하고, 독립 검토 수정 후 v2로 새 실행한 결과를 비교에 사용했다. 기준을 출력에 맞춰 바꾸지 않았다.

독립 내용 검토에서 이력서의 `인터뷰를 바탕으로`가 원자료에 없는 관계를 추가한다는 지적을 수정했다. GitHub 자동 검토는 보고서 예문에서 예산 승인과 실행 가능성을 연결한 점을 지적했다. 두 수정은 각각 독립 재검토로 확인했다. 상세 근거와 판본 해시는 [내용 검토 기록](content-review.md)에 있다.

보고서 예문을 고친 v3의 스킬 변경은 `references/reader-facing-reports.md` 한 파일이다. 이력서·문장 실행자가 읽은 파일은 v2와 v3에서 동일하다. 보고서는 [v3 동결 기록](regression-v3-freeze.json)에 따라 새 문맥에서 한 번 더 실행했고, 비교 평가자와 다른 새 평가자가 같은 기준으로 점검했다. v2의 최초 출력·점수는 그대로 두었다. 자동 검사·패키지·원격 검토의 범위는 [검증 기록](verification.md)에 있다.
