## 접근 범위와 증거

실행자는 한 실행에서 K5·K6 두 입력과 스킬 본문을 함께 받았고, 채점자는 두 입력·이번 출력·고정 루브릭만 제공받았다. 사례별 새 대화 실행이 아니므로 이 기록은 사례별 출력과 축 점수로만 쓰고, `protocol.md` 3단계의 사례별 독립 실행으로 집계하지 않는다. 실행자는 `rubric.md`를 읽지 않았고 채점자는 `SKILL.md`를 읽지 않았다. 참조 링크·다른 사례·과거 출력은 제공하지 않았다. 실행자·채점자의 접근 기록과 SHA-256을 함께 보존했다. 리드는 실행 전 고정한 네 파일의 해시와 실행 후 바이트 일치, 현재 스킬·루브릭과의 일치를 확인했다.

평가 리드는 실행·채점 역할의 도구 기록에서 허용 입력 읽기와 산출물 작성을 확인했다. API가 긴 도구 본문을 일부 잘랐으므로 완전한 시스템 접근 감사라고 주장하지 않는다. 공개 기록은 ephemeral 세션 식별자 대신 실행 역할, 허용 입력, 산출물 SHA-256과 관찰 가능한 접근 범위를 증거로 쓴다. 실행자·채점자 자체 보고와 관찰 가능한 도구 기록에서 다른 사례를 읽은 증거는 없었다.

채점자는 실행자 접근 이력을 받지 않아 실행 전체 판정을 보류했다. 그 판단을 수정하지 않았다. 리드의 수용 범위는 두 사례의 실제 실행, 지정 입력·출력 해시, 별도 채점 확보까지다. 공유 작업 디렉터리의 경로 허용 목록으로 격리했으며 OS 샌드박스는 사용하지 않았다. 두 실행 context에 기본 작업 지침 등이 이미 노출되어 있어 완전한 무맥락 실험도 아니다.

## 한계

실행자 1명·별도 채점자 1명의 내부 사례 검사다. 채점자 간 일치도, 일반화 가능한 효과, 스킬 전체 타당도, APA 규정 준수는 측정하지 않았다. 분석적 루브릭 전체가 아닌 동결한 세 축만 채점했다. 이번 근거는 `source-access-followup`의 문헌 조사와 별도이며, 과거 round-2의 실패·보류를 덮어쓰거나 누적 6/6으로 합산하지 않는다.

## 수용 상태와 루브릭 버전 (현 head 기준)

위 통과 판정은 동결 루브릭(`rubric.md` SHA-256 `a6006a30…`, manifest base `df5c6af`) 기준이다. 동결본과 현행 `evaluations/rubrics/three-axis.md`(SHA-256 `96022f61…`)의 git diff를 확인한 결과 채점표(0–3×3축 셀·통과 경계 각 축 2점)는 동일하고 측정학 프레임 설명 문구만 바뀌었다. 따라서 이 비교 기록이 동결본 비교 증거가 되며, 현 루브릭 재채점은 선택이다. 과거 판정을 덮어쓰지 않으며 새 스킬 실행·새 평가 통과로 집계하지 않는다.
