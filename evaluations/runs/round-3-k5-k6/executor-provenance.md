# 실행 접근 기록

## 실제 읽은 입력과 SHA256

- `K5.md`: `1c8afa28dbcacd8c755f9771350a00ef17f5280fa5d1f7e5c748cf68df3d911d`
- `K6.md`: `70ecc7c5505d3e5cc2001cb6a3b5ae0e1be66c4afe9f477ef90349286028d285`
- `SKILL.md`: `a510af3c1e8f342221665b8ba8c7d4a66276a3af2564efcfb27eb120bb477080`

실제 실행에는 세 파일만 있는 격리 작업공간을 사용했다. 로컬 절대경로는 재현 가능한 계약이 아니므로 공개 기록에서 제외한다.

## 출력

- `output.md` SHA256: `68abea1b1f2ec248e4b405e044f180db987334c6018140bcd90aa98a16c38c5c`

## 접근 제한 준수

- 지정된 입력 세 파일만 읽었다. SHA256 계산을 위해 같은 세 파일의 바이트를 다시 읽었다.
- 저장소 파일, 다른 사례, 과거 출력, 루브릭, 참조 파일, 메모리, 웹은 열지 않았다. `SKILL.md`의 링크도 열지 않았다.
- `output.md`는 작성한 UTF-8 바이트에서 SHA256을 계산했으며 출력 파일을 다시 읽지 않았다.
- 지정된 `output.md`와 이 provenance 기록만 작성했다. 다른 파일 수정 및 commit은 하지 않았다.
- 조정자 후속 지시는 실행 관리 채널로 확인했으며 파일 읽기 범위는 넓히지 않았다.
