# 온라인가나다 ‘한곳/한 곳’ 문맥 구분 진단 설계 (미실행)

- 근거: N-Q32, [2026-11-21 질문·2026-11-23 공식 답변 338751](https://korean.go.kr/front/onlineQna/onlineQnaView.do?mn_id=81&pageIndex=1&qna_seq=338751&searchCondition=&searchKeyword=); 직접 질문·답변 확인 2026-11-24.
- 적용판: 변경 전 PR #31 head `3504de4e782cbd85ae7ce1ceebfb457d6445b12c`에서 작성. **이 파일을 포함하는 최종 head와 제공 스킬·시나리오의 SHA-256은 평가 전 별도 고정해야 하며 이 파일을 실행 결과로 오해하면 안 된다.**
- 시나리오: [N-20261124-hankot](../../scenarios/blind-inputs.md#n-20261124-hankot--한곳한-곳의-문맥-구분-진단-입력)의 직접 쓴 KOT1~KOT4. 실행자는 원문과 사용자 요청만 받는다. 채점자는 별도로 원문과 아래 사전 기준을 검토한다.

## 사전 판정 기준

| 입력 | 기대 행동 | 실패 조건 |
| --- | --- | --- |
| KOT1 | 같은 장소라는 뜻이 명시된 경우 ‘한곳에서’로 **선택 제안 가능**. ‘한 곳에서’를 자동 오류라 단정하지 않고 원문 유지도 설명과 함께 허용 | 수량 표현과 동일 장소 표현을 문맥 확인 없이 모든 문장에 강제 치환하거나, 실제 기관 운영 사실을 발명 |
| KOT2 | 위치 한 개를 세는 ‘한 곳’을 유지 | ‘한곳’으로 기계적 치환, 시설 수·선정 사실 변경 |
| KOT3 | 등재 낱말 ‘한곳’을 유지 | ‘한 곳’으로 일괄 띄어쓰기 |
| KOT4 | 인용부호 안 원문을 보존 | 인용문을 변경하거나 인용 내용의 실제 출처를 만들어 냄 |

## 실행·판정 상태

- **작성/등록만 완료. 독립 실행 0건, 독립 채점 0건, 통과 판정 없음.** 지침·출처가 핵심 판단을 직접 공개하므로 나중에 실행해도 블라인드 품질 개선의 독립 근거로 계산하지 않는다.
- 실행 전 제공 파일과 대상 head SHA, 각 파일 SHA-256, 수행자·별도 채점자, 최초 출력·기준 적용·실패 여부를 기록한다. 파일 내용이나 채점 기준이 바뀌면 새 차수로 분리하고 옛 입력을 소급 수정하지 않는다.
- Python 3.14 locked 전체 unittest·구조·출처·공개 위생·diff·패키징 및 최신 독립 원문/내용 리뷰는 이 설계를 작성한 것과 무관한 별도 완료 조건이다.
