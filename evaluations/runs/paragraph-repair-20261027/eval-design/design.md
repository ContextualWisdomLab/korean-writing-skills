# 긴 문장·문단 교정 평가 설계

## 산출물과 상태

- 설계 식별자: `korean-paragraph-repair-20261027`, 기준 판본 `1.0`.
- 입력은 C01–C04 네 개다. C01은 한 원문에 최소 교정과 재구성이라는 두 결과를 요청한다. 이를 다섯 번째 사례로 세지 않는다.
- 네 원문은 설계자가 직접 쓴 합성 문단이다. **실제 사용자 원문이 아니다.** 기관·인물·사건·수치·문헌 정보는 가상이다. C03의 괄호 인용은 귀속 범위를 시험하기 위한 가상 설정이지 실제 자료의 근거가 아니다.
- 기대 수정문·모범 답안·실행 결과·점수는 만들지 않았다. 의미 앵커는 관계와 사실의 대조 명세이며 특정 어순이나 문장을 정답으로 지정하지 않는다.
- 입력과 채점 기준은 실행·채점 전에 SHA-256으로 고정했다. 이번 작업은 설계와 무결성 검증까지이며, 교정 실행·독립 채점·스킬 개선 판정은 아직 하지 않았다.

| 파일 | 역할 | 원문 어절 수 |
| --- | --- | ---: |
| `C01.md` | 복잡하지만 뜻이 분명한 중첩문: 최소 교정과 읽기 쉬운 재구성의 범위 비교 | 165 |
| `C02.md` | 행위자·지시 대상 전환 추적, 자연스러운 주어 생략 보존 | 169 |
| `C03.md` | 문장 나눔 뒤 조건·예외·부정·인용 귀속 보존 | 169 |
| `C04.md` | 정상문·기능적 반복·명사화 유지, 미확정 수식 범위 확인 | 164 |
| `criteria.json` | 의미 앵커 27개, 필수 점검 20개, 네 축 0–3점, 별도 중대오류 기준 | — |
| `design.md` | 노출·독립성 한계, 동결 해시, 실행·채점 전달 절차 | — |

어절 수는 각 파일의 원문 부분만 공백으로 나눈 값이다. 한국어 단어의 언어학적 분석값이라고 주장하지 않는다. 각 원문은 한 문단이며 150–300어절 범위다. 제목·요청·합성 자료 고지는 길이 계산에서 제외한다.

## 독립성과 알려진 노출

이 역할은 입력·사전 기준 설계자다. 기존 예문·평가·다른 조사와 이번 스킬 개정안은 읽지 않았고, 저장소 탐색·검색·Git 작업·웹 조사를 하지 않았다. 파일 읽기·쓰기 범위는 이 설계의 여섯 파일로 제한했다. 다만 다음 노출이 있으므로 **완전 블라인드 설계 또는 완전 독립 검증이라고 부르지 않는다.**

1. 상위 지침으로 저장소의 `AGENTS.md` 내용과 과거 근거·평가의 요약이 이미 제공되었다. 거기에 적힌 자료를 이번에 새로 열람한 것은 아니다.
2. 상위 필수 지침에 따라 설치된 `korean-editing`의 `SKILL.md` 본문을 읽었다. 의미 앵커·행위자·문장 나눔·명사화·과잉 교정·자연스러움에 관한 기존 절차가 설계자에게 노출되었다. 링크된 기존 예문·출처 장부·검증 자료는 열지 않았다.
3. `evidence-backed-skill-development`의 본문도 필수 관련 스킬로 읽었다. 독립 실행·채점·해시 동결 절차에 관한 기존 지침이 노출되었다. 연결 자료는 열지 않았다. 이번 역할에 적용되지 않는 저장소 조사·수정 절차는 소유 범위와 읽기 금지 때문에 수행하지 않았다.
4. 현재 설치 스킬과 향후 비교할 기준판·수정판의 동일 여부는 확인하지 않았다. 런타임 표시 모델은 `auto`이고 실제 고정 모델 식별자·서로 다른 모델 사용 여부는 확인하지 못했다. 독립 모델 평가라는 주장도 하지 않는다.
5. 역할과 접근 범위를 지시로 분리한 것이지 파일 권한·컨테이너로 격리한 것은 아니다. 향후 실행자·채점자도 자동 제공 문맥과 필수 스킬의 실제 노출을 별도로 기록해야 한다.

이번 설계는 사용자 요구와 편집 판단에 따른 운영용 평가다. 외부 규범이나 연구를 새로 확인했다는 주장, 채점 절단점의 실증적 타당화 주장은 없다. 기준에 맞춘 합성 자료 네 개만으로 일반 한국어 교정 능력·실제 사용자 경험·평가자 간 신뢰도를 입증할 수 없다. 요청문 자체에 보존 조건을 명시했으므로, 명시적 지시를 받은 교정의 수행을 보는 시험이며 무지시 상황의 자발적 오류 탐지까지 측정하지 않는다.

## 사례 설계 의도

### C01

첫 문장의 구조는 복잡하지만 요청자·시설팀·운영위원회의 행위와 조건은 추적할 수 있다. 최소 교정에는 명백한 표기 교정 지점을 두었으나 문장 경계와 배열을 유지하도록 요청했다. 재구성에는 관계를 쉽게 따라갈 수 있는 변경을 허용했다. 명사화 삭제나 문장 수 증가 자체는 성공 조건이 아니다. 조건부 검토를 승인으로, 신고 감소를 효과 입증으로 바꾸는 손상을 함께 확인한다.

최소 교정과 재구성은 각각 네 축으로 채점한다. 사례 대표 점수는 축별 두 결과의 최솟값이다. 두 결과의 점수와 오류 기록은 따로 보존한다. 어느 한쪽의 실패를 평균으로 숨기지 않는다.

### C02

행위자가 문단 중간에 바뀌고 재촬영 목록·공개 동의 대장·공개 보류 의견이 함께 등장한다. 한편 동일 행위자가 이어지는 정상적인 생략도 넣었다. 이름을 매 문장 반복하거나 모두 생략하게 만드는 시험이 아니라, 전환과 생략의 기능을 구별하는 시험이다. 촬영 상태 확인·공개 동의 확인·일정 승인은 서로 다른 업무다.

### C03

앞의 두 긴 문장을 실제로 나누도록 요청했다. 본문·증빙의 기한, 장애 기록에 따른 증빙만의 예외, 즉시 폐기하지 않는다는 부정과 자동 심사 포함의 차이를 추적한다. 인용문의 발언 주체와 그 발언을 설명하는 주체를 구별한다. 둘째 문장 전체가 괄호 인용의 적용 범위라는 정보는 요청문에 명시했으므로, 그 범위를 알 수 없다는 이유로 작업을 회피할 필요가 없다. 특정 문장 수나 유일한 인용 배치를 강제하지 않는다.

### C04

파일·허가의 구분을 위한 정상문과 반복, 원본성 보장이라는 기능적인 명사화를 유지할 수 있게 했다. 마지막 문장의 교육 조건은 신규 이용자만을 제한하는지 외부 연구자까지 제한하는지 결정되지 않는다. 그 두 해석을 가르는 질문을 하되, 답을 받기 전에 한쪽으로 재작성하지 않아야 한다. 분명한 앞부분까지 보류하면 수행 결함이다. 전문을 그대로 유지하고 정확한 확인 질문만 덧붙인 결과도 적절할 수 있다.

## 채점 원칙

자세한 운영 기준은 `criteria.json` 한 곳에 고정했다.

- **M — 의미·자료 보존:** 행위자·대상·조건·예외·부정·시점·수치·강도·인과·인용의 관계.
- **N — 한국어 자연스러움·읽기 흐름:** 주장·근거·전환을 따라가는 과정, 호응·지시의 안정성, 장르에 맞는 문체. 실제로 걸리는 위치를 근거로 든다.
- **O — 과잉 교정 억제:** 정상 표현·필요한 반복·생략·전문 명사화의 기능과 수정의 필요성.
- **S — 요청 범위·확인 판단:** 최소 교정/재구성 등 범위 준수, 필요한 부분만 질문, 분명한 부분은 실제 수행.

네 축은 각각 0–3점이다. 명사절 개수·문장 길이·변경률·특정 어휘의 출현 횟수로 자연스러움을 대신 평가하지 않는다. 길고 중첩된 문장을 유지했다는 이유만으로 최소 교정을 낮게 채점하지 않는다. 반대로 문장을 짧게 나눴어도 관계가 끊기면 자연스러움이 좋아진 것이 아니다. 명사화는 어려운 문장에 있더라도 자동 삭제하지 않으며, 관계를 분명하게 풀어 쓴 변경도 형식만으로 금지하지 않는다.

불필요한 질문·회피는 주로 S에서, 읽을 수 있는 교정 본문 자체의 흐름은 N에서 판단한다. 같은 현상을 여러 축에서 자동 중복 감점하지 않고, 서로 다른 손상이 있는 경우에만 이유를 각각 적는다.

중대오류는 `K-ACTOR`, `K-SCOPE`, `K-DATA`, `K-QUOTE`, `K-LOSS`로 별도 기록한다. 낮은 유창성이나 선택적 어휘 치환 자체는 중대오류가 아니다. C04에서 모호함을 보존했지만 질문을 빠뜨린 경우와, 한 해석을 사실로 확정한 경우도 구별한다. 한 손상에 코드가 여럿 해당해도 사건 수는 하나다.

사례 통과는 중대오류 없음, 네 축 모두 2 이상, 필수 점검 모두 충족일 때만 가능하다. 미판정·판정 불가는 통과로 세지 않는다. 0–12 합계는 보조 정보일 뿐이며 중대오류를 상쇄하지 않는다. 합성 네 사례의 통과를 일반적 개선이나 타당화로 보고하지 않는다.

## 향후 전달·실행 절차

1. 조정자는 아래 해시를 다시 확인하고, 비교할 두 스킬 스냅샷도 작성이 끝난 뒤 별도로 고정한다. 이 설계자는 스냅샷·실행 결과를 열지 않았다.
2. 새 실행자에게는 한 가지 선택된 스킬 스냅샷과 해당 `Cxx.md`만 전달한다. `criteria.json`, `design.md`, 다른 버전 결과·과거 평가·버전 대응표는 주지 않는다. 입력의 합성 자료 고지와 요청문은 함께 전달한다.
3. 실행자의 자동 문맥·필수 로드 스킬 노출을 기록한다. 전역 설치 스킬이 함께 노출되었다면 한 스냅샷만 노출된 실험으로 보고하지 않는다. 설계자 자신을 독립 실행자나 채점자로 재사용하지 않는다.
4. 실행 결과를 원형대로 고정한 뒤 새 채점자에게 해당 입력, 기준, 익명 결과를 전달한다. 어떤 버전인지 알려 주는 대응표는 채점 확정 전까지 별도로 둔다. 가능한 경우 각 결과를 독립 채점한 뒤 비교하며, C01의 두 결과 구분은 유지한다.
5. 채점 기록에는 사례 ID, 익명 결과 ID, 앵커별 대조, 필수 점검 상태, 축별 점수와 위치 근거, 중대오류 사건, 보류 사유를 남긴다. 출력 자체의 미제출과 관찰된 의미 왜곡을 구별한다. 실패·동점도 보존한다.
6. 조정자는 Python으로 사례 집합이 정확히 C01–C04인지, 중복 없이 네 개가 있는지 확인한다. C01의 두 결과는 각각 기록하되 한 사례로 집계한다. 결과가 두 버전이라면 각 버전에서 이 조건을 따로 확인한다.
7. 입력·기준 해시를 다시 확인한다. 결과를 본 뒤 기존 입력·기준·실패 기록을 고쳐서는 안 된다. 해석 정정이 필요하면 기존 파일을 남긴 채 별도 판본·정정 기록을 새로 승인받아 관리한다. 이 역할은 소유한 여섯 파일 밖에 정정 파일을 만들지 않는다.

## 동결 해시

동결 범위는 요청문·합성 고지를 포함한 입력 네 파일과 `criteria.json`의 UTF-8 전체 바이트다. 줄바꿈 변경도 다른 바이트로 판정한다. 이 설계 문서는 해시 명세를 담는 메타데이터이므로 자기 자신을 재귀 해시하지 않는다. 향후 조정자는 필요하면 이 문서의 해시도 별도 실행 명세에 고정할 수 있다. 해시 일치는 무결성 확인이지 외부 공증·접근 통제·완전 블라인드의 증거가 아니다.

| 파일 | SHA-256 |
| --- | --- |
| `C01.md` | `a10e81de9244554f550127afbcda304a92f727e4f9c627a8773c2197986f977b` |
| `C02.md` | `f87f9559ff575982382c0585285b1cedd4a5abe062e80d4ec909d795ec290fd4` |
| `C03.md` | `c2389e8c227ef6f149854edcd9033ea3751da1f1d1e6854d3ba0ea5598b155ef` |
| `C04.md` | `478c83b2186f250628baed856a2a0661f80cb029ce90e47e7a701289a31afef8` |
| `criteria.json` | `c772363a107415f31059b55fb3f1890c23ca2907bdffd871553413e686d743cd` |

`eval-design`을 작업 디렉터리로 한 Python에서 다음 검증을 재실행할 수 있다. 이 코드는 여섯 소유 파일 이외의 파일을 탐색하거나 쓰지 않는다.

```python
from pathlib import Path
import hashlib
import json

root = Path.cwd()
expected = {
    "C01.md": "a10e81de9244554f550127afbcda304a92f727e4f9c627a8773c2197986f977b",
    "C02.md": "f87f9559ff575982382c0585285b1cedd4a5abe062e80d4ec909d795ec290fd4",
    "C03.md": "c2389e8c227ef6f149854edcd9033ea3751da1f1d1e6854d3ba0ea5598b155ef",
    "C04.md": "478c83b2186f250628baed856a2a0661f80cb029ce90e47e7a701289a31afef8",
    "criteria.json": "c772363a107415f31059b55fb3f1890c23ca2907bdffd871553413e686d743cd",
}
case_ids = ["C01", "C02", "C03", "C04"]
assert len(case_ids) == len(set(case_ids)) == 4
assert set(expected) == {f"{c}.md" for c in case_ids} | {"criteria.json"}
for name, digest in expected.items():
    actual = hashlib.sha256((root / name).read_bytes()).hexdigest()
    assert actual == digest, (name, actual, digest)

criteria = json.loads((root / "criteria.json").read_text(encoding="utf-8"))
assert criteria["상태"] == "실행·채점 전 사전 기준"
assert set(criteria["사례"]) == set(case_ids)
assert criteria["단위"]["입력_수"] == 4
assert criteria["단위"]["입력_ID"] == case_ids
assert [a["ID"] for a in criteria["축"]] == ["M", "N", "O", "S"]
assert all(set(a["점수"]) == {"0", "1", "2", "3"} for a in criteria["축"])
assert criteria["중대오류"]["점수와_분리"] is True
assert len(criteria["중대오류"]["코드"]) == 5
counts = {}
all_anchors = []
all_checks = []
for case_id in case_ids:
    text = (root / f"{case_id}.md").read_text(encoding="utf-8")
    marker = "\n## 원문\n\n"
    assert text.count(marker) == 1
    source = text.partition(marker)[2].strip()
    assert len(source.splitlines()) == 1
    counts[case_id] = len(source.split())
    assert 150 <= counts[case_id] <= 300
    assert counts[case_id] == criteria["사례"][case_id]["어절수"]
    assert "실제 사용자가 제공한 원문이 아니다" in text
    assert "의미_앵커" not in text
    all_anchors.extend(a["ID"] for a in criteria["사례"][case_id]["의미_앵커"])
    all_checks.extend(p["ID"] for p in criteria["사례"][case_id]["필수_점검"])
assert len(all_anchors) == len(set(all_anchors)) == 27
assert len(all_checks) == len(set(all_checks)) == 20
assert (root / "design.md").is_file()
print("동결 해시 5개·합성 입력 4개·네 축·앵커 27개·점검 20개 확인", counts)
```

## 작업 기록과 다음 책임

| 담당 | 완료한 범위 | 완료 기준·증거 | 다음 조치·의존성 |
| --- | --- | --- | --- |
| 평가 설계자 | 합성 입력 4개, 분리 기준, 설계 문서 작성 | 소유 파일 6개. 원문 길이·개수·JSON 구조·중복 없는 앵커·동결 해시를 Python `assert`로 검증 | 설계 완료. 기대 수정문·실행·채점은 수행하지 않음 |
| 조정자 | 이번 역할의 완료 범위 아님 | 해시 재확인, 선택 스킬 스냅샷·노출 기록·익명 대응표가 필요 | 새 실행자를 배정하고 입력과 기준의 전달을 분리 |
| 독립 실행자·채점자 | 아직 실행·채점 없음 | 고정된 출력과 근거 있는 점수·오류 기록이 필요 | 실행자에게 기준 비공개, 채점자에게 버전 대응 비공개. 이후 집계도 Python으로 검증 |

파일 권한 격리나 외부 검증은 하지 않았다. 저장소 수정·커밋·원격 게시도 이번 소유 범위가 아니므로 수행하거나 완료했다고 주장하지 않는다.
