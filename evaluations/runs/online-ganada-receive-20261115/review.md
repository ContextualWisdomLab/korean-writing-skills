# 2026-11-15 ‘-받다’ 평가의 정답 누출 정정 — 독립 실행 전 동결 후보

## 기존 판본과 수정 이유

- 근거: 국립국어원 온라인가나다 [338384 「승인 받다는 틀린 말인가요」](https://www.korean.go.kr/front/onlineQna/onlineQnaView.do?mn_id=201&pageIndex=1&qna_seq=338384). 질문일 2026-11-12, 공식 답변일 2026-11-13, 최초 원문 확인일 2026-11-13. 상담의 조사 유무 구별과 사전 관련 설명은 `source-ledger.md`의 **N-Q21**을 따른다. 이번 문서는 공식 답변의 추가 수정이나 신규 규정이 아니다.
- 원래 동결 과제: [2026-11-13 입력·기준](../online-ganada-receive-20261113/review.md). 원래 입력과 당시 기준은 **그대로 보존**한다. 실제 독립 실행·채점 결과는 없다.
- [2026-11-15 제출 CodeRabbit 리뷰](https://github.com/ContextualWisdomLab/korean-writing-skills/pull/31#pullrequestreview-5908070140)는 원래 입력 4의 정답 구절 `중요한 성과로 인정받은 자료`가 실행자가 읽을 수 있는 N-Q21 출처 장부에 **그대로 노출**된다고 지적했다. 앞서 지침 예문 세 개를 교체한 것만으로는 이 장부의 누출을 제거하지 못한다. **원래 입력 4를 블라인드 독립 평가 통과 증거로 사용하지 않는다.**
- 출처 장부를 실행자에게서 빼면 현행 `SKILL.md`의 출처 확인 경로까지 제한하게 된다. 장부·공식 근거는 보존하고 **새 문맥의 입력 4**를 별도 차수로 사전 동결하는 방식을 택한다.

## 후속 독립 실행 차수의 입력·기준 (실행 전 동결 설계)

| 번호 | 교정 입력(모두 직접 작성) | 사전 고정 기준 행동 |
| --- | --- | --- |
| R1 | `신약은 미 FDA의 승인을 받았다.` | **유지**: 목적격 조사 `을`이 있는 표현을 잘못된 피동이라며 강제 치환하지 않음. 원래 과제 1과 동일하며, 독립 실행에서는 새 대화에 제공. |
| R2 | `그 신약은 승인 받았다.` | **수정**: `그 신약은 승인받았다.` 접미사 결합 띄어쓰기만 고침. 원래 과제 2와 동일. |
| R3 | `식약처에서 허가를 받았다.` | **유지**: 조사를 임의로 삭제하지 않음. 원래 과제 3과 동일. |
| R4 (교체) | `그 소설은 독창성을 인정 받아 문학상을 받았다.` | **수정**: `그 소설은 독창성을 인정받아 문학상을 받았다.` 동사 `인정받다`의 붙임만 고침. 작품의 수상 여부·주체·시제는 그대로 두고, 뒤의 `문학상을 받았다`는 동사구를 붙이지 않음. |
| R5 | `관련 기관이 후보 약물을 승인했다.` | **유지**: 능동 구조와 기관·승인 사실을 바꾸지 않음. 원래 과제 5와 동일. |

- **입력 교체는 R4만**이다. 나머지 원래 동결 과제·기준을 소급 수정하거나 기존 판본에서 성공한 것처럼 표기하지 않는다. R1–R3·R5를 원본과 재사용하는 제한도 남긴다. 본 설계는 해당 표현 하나의 정답 문자열 중복을 해소하려는 **좁은 보완**이며 블라인드 독립성 전체를 증명하지 않는다.
- 실행 전 입력 R4 및 그 **교정된 완전 문장**이 실제 실행자에게 제공할 `skills/korean-editing/SKILL.md`, `references/orthography-decisions.md`, `references/source-ledger.md` 및 다른 전달 파일에 정답 사례로 그대로 존재하는지 확인한다. 본 기준표는 실행자에게 제공하지 않는다.
- 실행자에게는 각 사례의 **입력 문장과 해당 스킬·참조 파일만** 제공한다. 출처 장부는 현행 스킬 참조로 허용하지만, 이 평가 문서·기준·원래 동결 평가·채점 내역은 제공하지 않는다. 실제로 전달한 상대 경로의 목록, 각 파일 해시, 적용 PR head SHA와 입력 해시를 실행 **전에** 기록한다. 사례마다 새 독립 문맥에서 수행하고 첫 출력의 SHA, 수행 시각·차수, 독립 채점자의 결과를 별도 보존한다.
- 사례별 의미 보존·교정/유지·과잉 수정 억제와 행위자·기관·사실·시제 보존을 판단한다. 원문에 없는 승인·수상·기관 사실을 창작하거나 뒤의 `문학상을 받았다`까지 잘못 붙이면 R4 실패로 판정한다. 숫자·부정·조건이 없는 문장에 관련 사실을 새로 넣지 않는다.
- **2026-11-15 현재 실제 실행·출력 해시·별도 채점 결과는 없음.** 이 문서의 입력·기대 행동은 **검증 결과가 아니며** 전후 개선율·일반적인 한국어 교정 타당도 또는 전체 테스트 통과를 입증하지 않는다. 완료하려면 [독립 평가 절차](../../protocol.md)에 따라 원문과 평가 기준을 분리하여 실제 실행·채점을 기록한다.

## 2026-11-15 프로토콜 정합성 보완 (독립 실행 전)

[독립 평가 프로토콜](../../protocol.md)은 실행자에게 [등록된 시나리오 파일](../../scenarios/blind-inputs.md) 중 담당 사례만 제공하도록 정한다. 이전 판본은 R1–R5 입력을 이 평가 문서에만 두어 프로토콜과 맞지 않았다. 이번 변경에서 R1–R5를 blind-inputs.md에 별도 섹션으로 등록했다.

등록 파일이 바뀌었으므로 이전 차수의 freeze.json 또는 기존 해시를 새 평가에 승계하지 않는다. 실행 **전** 최종 head와 시나리오 파일 및 전달할 스킬·참조 파일 각각의 SHA-256과 사례 ID를 다시 기록한다. 평가 기준과 답변, 원래 동결 평가 문서는 실행자에게 제공하지 않는다. 현재는 시나리오 등록과 절차 수정만 완료했으며 실제 실행·채점·최종 해시 고정은 하지 않았다.
