# 경력자 지원 문서 독립 평가 — 최초 판정

**판정: 통과.** 경력자 지원 문서의 8개 항목을 모두 충족하며, 의미 보존·자연스러움·요청 범위·형식은 각각 3점이다. 중대 오류는 없다.

## 평가 범위

`criteria.md`, `resume-input.md`, `resume-output.md`, `cover-output.md` 네 파일만 읽었다. 기준의 공통 판정과 경력자 지원 문서 항목을 적용했으며, 연결된 별도 루브릭이나 다른 출력·진단·스킬은 읽지 않았다. 정답 문구 일치나 수정량은 평가하지 않았다.

## 항목별 판정

| 항목 | 판정 | 입력과 출력 대조 및 근거 |
|---|---|---|
| 1. 중심 역할 보존 | 충족 | 입력: UX 리서처로 시작했으며 현재 서비스기획 PM이다. 출력: “UX 리서처로 경력을 시작한 서비스기획 PM입니다.” 경력의 중심 역할을 보존했다. 자료 없는 개발 총괄·혁신 리더 주장은 없으며, 제목의 리드 지원은 지원 직무를 뜻한다. |
| 2. 직급·프로젝트 역할·기간·조율 경험 구분 | 충족 | 입력: 해솔시스템 선임과 PM 역할, 누리랩 2019.03~2022.02 및 2020~2021년 3명 과제 조율, 프리랜서 2017~2020년과 재직 일부 병행. 출력: “직급: 선임 · 프로젝트 역할: 서비스기획 PM”; 누리랩 기간과 기획·개발·QA 3명의 우선순위·검수 일정 조율; 프리랜서 기간과 누리랩 병행 표시. 직급과 역할, 조직 및 과제 기간을 구별했다. 공식 팀장이나 병행 기간을 합산한 총경력을 만들지 않았다. |
| 3. 최신 학력 정정 반영 | 충족 | 입력: 정보디자인 전공·경영학 복수전공으로 받은 학사 학위 하나. 출력: “학사: 정보디자인 전공·경영학 복수전공” 하나의 학사에 주전공과 복수전공이 연결된다. 오래된 복수 학사 표기로 되돌리지 않았다. |
| 4. 요약과 경력 근거 연결 및 반복 축소 | 충족 | 입력: 오래된 초안은 경력 요약·핵심 역량의 추상적 소개를 반복하고 학력 뒤에 상세 경력을 제시했다. 출력: 경력 요약 다음에 해솔시스템·누리랩·프리랜서 경력을 배치하고 학력은 마지막에 제시했다. 요약의 인터뷰·요구사항·검수·조율·비용 검토를 상세 경력에서 확인할 수 있다. 독립적인 추상 역량 목록과 동일 소개 반복을 줄였다. |
| 5. 검색 과제 기여와 구현·피드백 구분 | 충족 | 입력: 본인 인터뷰 12명·검수 시나리오 18개·요구사항 반영, 협력사 구현, 시범 사용자 8명 중 5명의 정성 의견, 시간·비용 효과 미측정. 출력: 12명 인터뷰와 요구사항 반영, 18개 검수 시나리오, “화면 구현은 협력사가 담당”, 8명 중 5명의 찾기 쉬워졌다는 의견과 효과 미측정 표시. 개인 기여와 협력사 구현을 정확히 나눴고 정성 피드백을 보존했다. 전체 사용자의 생산성·정착 효과나 확정된 인과로 확대하지 않았다. |
| 6. 비용 계산표와 과제 기간 보존 | 충족 | 입력: 운영비 검토 2025.03~2025.06의 실제 요청량·공급자 단가 기반 비용 계산표; 검색 과제는 2024.02~2024.11; 채택·실제 절감액 자료 없음. 출력: 운영비 검토와 검색 화면 개선의 기간을 따로 표시하고 “사용 규모별 비용 계산표 작성”으로 기재했다. 계산표 작성 경험을 살렸으며 제안 채택이나 실제 절감을 주장하지 않았다. 미확인 사항을 반복 설명하지 않아도 사실관계가 유지된다. |
| 7. 자기소개서의 관점·학습·미래 방향 연결 | 충족 | 입력: 사용 횟수는 필요하지만 단독으로 업무 개선 판단 불가; 검색 과제로 업무 순서를 배움; 다음 직장에서 기능·절차 및 사용 규모·업무 품질을 함께 확인하고 싶음. 출력: 사용 횟수의 필요성과 한계를 설명하고 인터뷰에서 업무 순서를 배운 경험을 거쳐, 다음 직장의 기능·절차 검토와 사용 규모·업무 품질 확인 계획으로 이어진다. 지표 전체를 부정하거나 미래 방향을 과거 성과로 바꾸지 않았다. 검색 과제의 사실은 관점을 뒷받침하는 근거로 사용했으며 이력서 문단을 그대로 반복하지 않았다. |
| 8. 제출용 한국어 Markdown 및 길이 제한 | 충족 | 입력: 이력서 1,800자, 자기소개서 700자 이내의 두 부분; 제목·목록 표시·공백·줄바꿈 포함; 연락처 제외. 출력: 이력서 679자, 자기소개서 476자. 각 파일이 제목을 포함하는 독립 문안이며 연락처·편집 해설이 없다. 한국어 제출 문안의 구획이 명확하고 두 제한을 모두 지킨다. 조사 메모나 편집 설명이 본문을 대신하지 않는다. |

## 세 축 점수

| 축 | 점수 | 근거 |
|---|---:|---|
| 의미 보존 | 3/3 | 최신 학력 정정, 중심 역할, 기여 주체, 기간, 정성 의견의 범위와 미래 방향을 보존했다. 근거 없는 실적이나 인과를 추가하지 않았다. |
| 자연스러움 | 3/3 | 이력서는 경력별 간결한 목록 형식이 일관되고 자기소개서는 지원 이유·경험·계획이 자연스럽게 연결된다. 문서 용도에 맞는 명사형 목록 종결은 감점하지 않는다. |
| 요청 범위·형식 | 3/3 | 연락처 없는 두 한국어 Markdown 문안이며 글자 수 제한을 지킨다. 제출 본문에 조사 메모나 편집 해설을 넣지 않았다. |

각 축 2점 이상이고 중대 오류가 없으므로 통과한다. 점수 합계로 중대 오류를 상쇄하지 않았다.

## 중대 오류

**없음.** 없는 실적·수치·학위·직책·개인 기여·확정 인과, 팀 행동의 오귀속, 제안을 승인·완료로 바꾼 표현을 발견하지 않았다.

## 실제 문자 수

| 문안 | 실제 문자 수 | 상한 | 결과 |
|---|---:|---:|---|
| 이력서 (`resume-output.md`) | 679 | 1,800 | 충족 |
| 자기소개서 (`cover-output.md`) | 476 | 700 | 충족 |

UTF-8로 읽은 각 파일의 Unicode 문자 수를 계산했다. 제목·Markdown 목록 표시·공백·모든 줄바꿈과 마지막 줄바꿈을 포함한다. 파일 전체가 요청 문안으로 명확하여 제외한 구분용 해설은 없다.

## 의미가 같은 표현의 처리

- 학사 뒤에 전공·복수전공을 연결한 표기는 학사 학위 하나의 의미를 전달하므로 “하나”의 문자 일치를 요구하지 않는다.
- 지원 대상인 리드 표기는 과거 또는 현재 공식 직책 주장으로 보지 않는다.
- 자기소개서에서 검색 과제 사실을 관점의 근거로 다시 쓰는 것은 이력서 문단의 그대로 반복과 구별한다.
- 미확인 제안 채택·절감액을 주장하지 않은 문안에 그 제한을 별도 괄호로 반복할 것을 요구하지 않는다.

## 판정의 범위와 보존

합성 과제 두 문안의 텍스트 적용 확인이다. 실제 채용 성과, 한국어 전체 품질, 채점자 일치도 또는 DOCX/PDF 조판을 검증한 결과가 아니다.

최초 출력은 수정하지 않았으며, 평가 전후 원본 파일의 SHA-256 동일 여부를 확인했다. 이 파일은 최초 판정으로 보존한다.
