# 감사 표현과 격식 선택의 진단 설계 (미실행)

- 근거: N-Q33, [국립국어원 338762 「화가납니다」](https://www.korean.go.kr/front/onlineQna/onlineQnaView.do?mn_id=201&pageIndex=1&qna_seq=338762&searchCondition=&searchKeyword=); 질문일 2026-11-22, 공식 답변일 2026-11-23, 최초 열람일 2026-11-24.
- 대상: evaluations/scenarios/blind-inputs.md의 N-20261124-thanks (TH1~TH4). 이 설계의 생성 전 head는 f796a0e1d52502fdf9971c24e6d64d7b9a4d6ec3. 실제 실행 전 새 head, 스킬·전달 자료·입력·판정 파일 SHA-256을 고정한다.

## 사전 판정 기준

| 입력 | 기대 행동 | 실패 조건 |
| --- | --- | --- |
| TH1 | 일상적인 높임의 ‘감사해요’를 문법상 맞는 표현으로 유지 | 무조건 명령문/오류로 단정, 원하지 않는 문체 변경 |
| TH2 | 명시된 하십시오체 통일 요청에 따라 ‘감사합니다’로 문체 변경 가능 | 문체 변경을 규범 오류 수정으로 설명하거나 뜻 변경 |
| TH3 | ‘기대가 됩니다’의 주격 조사와 문법 구성을 유지 | ‘기대됩니다’로 필수 자동 치환, 의미·시제 변경 |
| TH4 | 원문 인용을 그대로 보존 | 인용 안의 감사 표현을 조용히 변경 |

## 실행·검증 상태

**설계만 완료, 독립 실행 0건, 채점 0건, 통과 판정 없음.** 스킬·근거에서 답이 노출될 수 있어 미래 실행도 독립 블라인드 성능 개선 증거로 쓰지 않는다. 실제 검증 시 최종 head와 파일 해시·실행자·별도 채점자·첫 출력·판정 기록을 남긴다. 최신 head의 Python 3.14 uv locked 전체 검사·스킬 구조·출처·공개 위생·diff·두 preview 패키징과 작성자 이외의 실제 내용 검토는 별도 필요하다.
