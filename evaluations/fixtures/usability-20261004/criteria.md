# 합성 3사례의 독립 평가기준

## 범위와 접근 분리

- 이 패킷은 한국어 편집 2사례(K17·K18)와 APA 원고 정리 1사례(A3)의 제한 범위 합성 평가 설계다. 실제 팀 사용 평가인 Issue 2의 실사용 자료나 결과가 아니다. 합성 통과를 실사용성·일반적 효과·성능 향상·APA 전면 준수의 증거로 바꾸지 않는다.
- 제작자는 저장소의 `AGENTS.md`, `evaluations/protocol.md`, `evaluations/rubrics/three-axis.md`만 평가 원칙으로 읽었으며 평가 대상 스킬 본문, 작성자 정답, 실행 출력은 읽지 않았다. 예문은 직접 작성했다. 모범 교정문·예상 출력·사전 부여 점수는 만들지 않았다.
- 실행자에게는 담당 입력 한 개와 준비된 대상 스킬 및 필요한 근거 파일만 준다. 이 파일과 `freeze.json`, 다른 입력·결과·채점 정보는 제공하지 않는다. K17·K18은 한국어 편집, A3은 APA 원고 작성 스킬을 사용하며 사례마다 새 context의 별도 실행자를 둔다.
- 채점자는 이 기준, 해당 입력, 실제 출력만 대조한다. 스킬 본문과 작성자 정답은 읽지 않는다. 실행자·채점자·제작자는 분리하며 접근 이력 확인은 후속 운영자의 책임이다. 같은 저장소에 있는 파일의 이름이나 해시는 실제 접근 통제를 보증하지 않는다.
- 여기서 제시하는 항목과 0–3점 설명은 프로젝트 평가판단이다. 새 외부 규정은 조사하지 않았다. 공적 어문 규정이나 APA 공식 채점표로 제시하지 않는다. 특정 APA 절·쪽·규정 위반 판정은 공식 원문을 직접 확인한 별도 증거 없이는 하지 않는다. 해당 검증의 보류와 제공 자료만으로 판정 가능한 사실보존을 구별한다.

- 사례 통과는 세 축 각각 2점 이상이고 중대 오류가 없는 경우다. 합산·평균·가중치로 실패를 상쇄하지 않는다. 내부 수용 경계이며 검증된 절단점이 아니다.
- 중대 오류는 무근거 인과·유의성 확정, 수치 또는 인용 변조, 행위자·IRB·동의·서지·규정 조항 발명, 미확인을 부재로 단정, 프로젝트 조건의 보편 규칙화다. 발견하면 축별 점수와 별개로 사례 실패를 기록한다.
- 미실행·빈 응답·담당 사례 외 정보 접근 등 독립성 위반은 보류이며 통과에 포함하지 않는다. 세 사례 모두 통과해야 이 패킷의 실행 통과다.
- 허용되는 편집 형태는 하나가 아니다. 문자열 일치, 수정량, 능동문 비율을 점수 근거로 쓰지 않는다. 모든 문장을 고치거나 질문을 늘리는 것 자체는 가점이 아니다. 답할 수 있는 부분까지 전부 거부하면 요청 수행 여부를 평가한다.
- 채점 기록은 사례 ID, 축별 점수 3개, 항목별 충족·위반·판정 불가, 입력과 출력의 짧은 대응 근거, 중대 오류 여부, 통과·실패·보류, 검증 한계를 포함한다. 입력의 오주장을 그대로 보존하는 것과 제공 근거의 범위로 바로잡는 것을 혼동하지 않는다.

## K17 — 번역투와 추정·수치·인용 귀속

### 의미 보존 확인 항목

- 같은 60개 합성 응답을 두 차례 검토했다는 대상과 반복 범위를 유지한다. 별개의 응답자 집단이나 실측 연구로 바꾸지 않는다.
- 정확한 선택의 수 36개·48개, 각 60%·80%, 차이 20%포인트를 유지한다. 비율과 비율 차이, 상대 증가율을 혼동하지 않는다.
- 문의 유형 12종·9종을 문의 건수로 바꾸지 않는다. 근거 없는 비율·효과크기·검정 결과를 추가하지 않는다.
- 안내문과 예시 배치를 함께 바꾸었고 각각의 영향은 분리 검토하지 않았다는 조건을 유지한다. 안내문 수정의 효과는 가능성이지 입증된 원인이 아니다. 검정 미실시와 실제 업무 오류 감소를 결론 낼 수 없다는 범위를 유지한다.
- 직접 인용은 가상 문서의 작성자 민서에게 귀속한다. 인용 내용은 변조하지 않는다. 인용 부호를 유지하거나 내용을 정확한 간접 인용으로 전환하는 편집은 모두 인정한다.
- 예시 배치 영향의 가능성은 검토자 준호의 논평이며 민서의 직접 인용이나 입증된 결과가 아니다. 두 사람의 발언을 합쳐 한 사람의 주장으로 만들지 않는다. 가상 문서에 실제 출처·서지를 붙이지 않는다.

### 자연스러움·과잉 교정 확인 항목

- 중첩된 추정 표현, 목적을 나타내는 장황한 명사구, 반복 설명을 읽기 쉽게 정리하되 불확실성 자체를 지우지 않는다. 수정 여부나 특정 문구의 사용을 강제하지 않는다.
- 동료 분석자가 읽는 검토 메모의 논리 흐름과 원문에 가까운 분량을 유지한다. 요약 때문에 핵심 제약이 사라졌는지 확인한다.
- 피동·명사화·학술 용어를 일괄 제거하거나 새 행위자·정책 제안을 끼워 넣지 않는다. 설명은 주요 수정 근거에 한정한다.

## A3 — 방법·결과 정리와 사실 발명 억제

### 의미·APA 사실보존 확인 항목

- 입력은 실측 연구가 아니라 가상 연구와 합성 요약치다. 결과물을 실제 참여자에게서 관찰·검정한 성과로 제시하지 않는다. 이 한계는 결과물이나 동반 설명에서 식별 가능해야 한다.
- 초대 90건 → 응답 72건 → 과제 이해도 문항 결측 8건 제외 → 분석 64건, X·Y 각 32건을 유지한다. 90건이 모두 분석되었다고 쓰거나 건수를 새로운 인구학적 사실로 확장하지 않는다.
- 단일 시점 비교라는 범위와 자료 배정 절차 미제공을 유지한다. 무작위 배정, 종단 변화, 무작위 실험·인과 설계를 발명하지 않는다.
- 1–5점이며 높은 점수가 높은 이해도를 나타낸다는 정보와 평균 X 3.4·Y 3.1을 유지한다. 문항 수·도구명·신뢰도·표준편차·표준오차·신뢰구간·검정통계량·자유도·p값·효과크기·분석 프로그램을 추정하지 않는다.
- 초안의 유의성과 개선 효과 확정은 제공 요약치로 뒷받침되지 않는 주장으로 처리한다. 통계 검정이 없으므로 유의하지 않다고 확정하는 것도 인정하지 않는다. 주어진 평균의 단순 산술 차이는 새 통계 분석으로 포장하지 않은 경우 허용하며 작성 의무는 아니다.
- IRB 승인·면제·승인번호·동의 획득 여부를 사실로 채우지 않는다. 기록 미제공을 미승인·동의 미실시로 단정하지 않는다. 확인 질문이나 분명한 미제공 표시로 처리하는 여러 방식이 가능하다.
- 모집·인구학·수집 시기·배정·도구 정보와 윤리·동의 기록을 본문 사실과 구별하여 확인 대상으로 다룬다. 새로운 결측 처리나 제외 기준을 추가하지 않는다.
- Method·Results의 제공 정보로 작성 가능한 본문과 투고 전 확인 질문을 구분한다. 미제공 항목 때문에 전체 작업을 대체하는 일반론만 제시하지 않는다.
- 제공되지 않은 학술지 지침이나 APA 절·쪽을 만들지 않는다. 한국어 어순에 영어 문법을 강제하거나 이 가상 사례의 제한을 모든 연구의 규칙으로 확장하지 않는다.

### 자연스러움·과잉 교정 확인 항목

- 방법과 결과의 역할을 구분하고 이해 가능한 한국어 학술 문장으로 정리한다. 확인 질문은 본문과 섞여 사실처럼 읽히지 않아야 한다.
- 불필요한 서론·논의·참고문헌, 가짜 분석표, 완성되지 않은 값을 완성된 수치처럼 제시하는 형식을 추가하지 않는다. 내용이 명확하면 표·문단·목록 등 형식 선택 자체는 감점하지 않는다.
- APA 형식 검증은 사실보존과 별개다. 이번 기준만으로 APA 전면 준수·위반을 판정하지 않는다.

## K18 — 표·운영 보고와 행위자·미확인 구분

### 의미 보존 확인 항목

- 2026년 9월 30일 보고 시점, 작업 총 7건과 완료 4건·진행 중 2건·보류 1건의 대응을 유지한다.
- 배포 완료 사실과 실행자 이름 미기재를 구분한다. 배포 후 점검과 공급사 일정 회신 요청은 운영팀의 행위다. 그 사실만으로 배포 실행자나 공급사의 회신 작성 담당자를 운영팀으로 정하지 않는다.
- 로그 확인 범위는 완료 작업 4건 중 3건 확인·1건 미확인이다. 나머지 3건은 이번 점검 대상이 아니며 전체 7건의 로그를 확인한 것처럼 확장하지 않는다.
- 로그 미확인 1건을 로그 부재·기록 실패로 바꾸지 않는다. 원인 자료 미전달·장애 원인 미확인을 원인 없음이나 특정 원인 확정으로 바꾸지 않는다.
- 경보 0건은 14:00–15:00 점검 구간의 기록이다. 하루 전체 무경보·무장애 또는 정상 운영을 확정하지 않는다.
- 공급사 일정 회신 미접수와 보류 작업 완료 시점 미확정을 유지한다. 공급사 거절·지연 사유·완료 날짜·후속 점검 담당자를 발명하지 않는다.

### 자연스러움·과잉 교정 확인 항목

- 표 형식을 유지하며 각 항목의 상태·확인 범위·후속 정보가 대응해야 한다. 간결한 표의 명사구를 문장으로 모두 바꾸거나 항목을 무리하게 합치지 않는다.
- 알고 있는 행위자는 식별 가능하게 하고 모르는 행위자는 추정하지 않는다. 행위자가 불명인 피동문을 유지하거나 정보 부족을 명시하거나 별도 질문을 남기는 방법은 모두 허용한다.
- 수동 표현 제거를 목표로 모든 문장의 주어를 운영팀으로 채우지 않는다. 불확실성 구분에 필요한 문장과 용어를 불필요한 반복이라고 삭제하지 않는다.
- 내부 운영 보고의 문체로 읽기 쉽게 고치되 근거 없는 책임 추궁·조치 약속·원인 진단을 추가하지 않는다.

## 동결과 후속 실행 계약

- `freeze.json`에는 세 입력과 이 기준 파일의 실제 바이트를 대상으로 한 SHA-256만 파일별로 기록한다. 스킬·근거·실행 출력·독립성 운영 기록의 해시는 포함하지 않는다.
- 동결은 입력과 판정기준이 후속 실행 전 어떤 내용이었는지 대조하는 수단이다. 이 제작 단계에서는 실행·채점하지 않았으며, 후속 운영자는 실행 직전에 네 파일 해시를 재검증해야 한다. 불일치하면 실행을 보류하고 새 판본으로 별도 동결한다. 실행 후 기준을 바꿔 기존 통과를 만들지 않는다.
- 해시 일치는 준비 시점의 내용 동일성만 입증한다. 타임스탬프 공증·변경 불가능한 보관·원격 커밋·스킬 준비 완료·실제 블라인드·실사용성·효과·채점자 일치도·타당도를 입증하지 않는다.
- 후속 실행자는 별도 기록에 대상 스킬·사용 근거 버전과 실제 출력 해시, context 격리 여부, 접근 범위를 남긴다. 채점자는 실제 출력 확보 뒤에만 점수를 부여한다. 공개 기록에는 저장소 상대 경로만 쓰고 로컬 절대경로·임시 세션 식별자·개인정보·비밀을 남기지 않는다.
